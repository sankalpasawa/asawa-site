Key Insight: Three Types of System Files

Flow Files (22)
Directly activate during problem solving. Have a specific trigger point in the v2 flow (Phase 1-9). If removed, a step in the flow breaks.

These are the operational core.
Governance Files (28)
Loaded at session start or on-demand. Constrain agent behavior across ALL phases. Don't activate at a specific step -- they're the constitution the flow operates within.

These are the constraints. Remove one and behavior drifts.
Orphaned Files (18)
No activation in the problem flow AND not governance constraints. Either superseded, future-only (multi-agent), or belong to a different flow (scheduling, onboarding, deployment).

7 to archive. 5 to hold for v3. 6 need their own flow diagram.
What's Actually Missing From the v2 Flow
1. Scheduling flow -- WEEKLY-PLANNING, DAILY-STANDUP, ROADMAP-MEETING have no home. They need a separate "Cadence Flow" diagram.
2. Company lifecycle flow -- CLIENT-ONBOARDING, DEPLOYMENT-MODEL, MANIFEST need a "New Company Flow" diagram.
3. Compliance Agent -- exists but references old lifecycle. Needs v2 rewrite to work with Domain Gate + Terminal Check.
4. Multi-agent coordination -- AGENT-PROTOCOLS, PARALLELIZATION-ARCHITECTURE, AGENT-INCENTIVES are designed but have no activation. Need v3 multi-agent flow.
5. Direction enforcement at runtime -- DIRECTION-ENFORCEMENT.md encodes D1-D10 as TRIGGER/CHECK but nothing in v2 flow actually runs these checks per-node. The enforcement is implicit (loaded at boot) not explicit (checked during execution).
