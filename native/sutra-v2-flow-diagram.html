Sutra v2 -- Complete Problem Flow

When a new problem statement arrives, this is everything that happens. Each block is a processing step.

1
Problem Arrives

Any input: founder task, TODO item, upstream node output, verbal instruction. Before anything else happens.

Input
Problem Statement
Raw input. Could be "fix this bug", "why aren't we growing", "build auth system", or "the site is down." No classification yet. No process yet. Just the problem.
|
2
Domain Gate

The PRIMARY gate. Fires before any scoring, estimation, or process selection. One question: "Is the cause-effect relationship known, discoverable, emergent, absent, or unclear?"

Domain Classification
Cynefin Gate
Classify the problem domain. This determines the RESPONSE PATTERN, not depth.
1.Ask: "Is the path from input to solution known, discoverable, emergent, absent, or unclear?"
2.Score resource intensity (ESI): how many systems, people, dependencies? (1-5)
3.OODA tempo cap: must classify in <30 seconds. If stuck, default to DISORDER.
4.If Cynefin ambiguous: fall back to Rumsfeld (known/unknown/unknown-unknown)
Cynefin (existing, promoted) ESI resource scoring (new) OODA tempo cap (new) Rumsfeld fallback (new)
→
Output
Two Signals
DOMAIN: Clear | Complicated | Complex | Chaotic | Disorder

RESOURCE: 1-5

PATTERN: Encode | Traverse | Probe | Stabilize | Decompose

After domain gate, existing 10-parameter scoring still runs. But it no longer produces depth. It feeds: appetite (budget), verification intensity, practice routing breadth.

|
routes to one of five patterns

3
Five Response Patterns

Each domain gets a fundamentally different execution shape. Not different depth of the same process -- different process entirely.

Pattern A -- Clear
ENCODE
Cause-effect known. Pattern exists. LLM encodes solution into a mechanism. Mechanism executes. LLM exits execution loop.
1.Load existing pattern (protocol store, prior code, known formula)
2.Pick encoding mechanism: code / SQL / spreadsheet / checklist / direct
3.LLM designs mechanism (function + tests + assertions)
4.Mechanism runs (not LLM). Tests pass/fail = verification.
5.If domain shifts mid-execution (node needs judgment) → pause, reclassify that node as Complicated, resolve, re-enter
Precision: temp=0, schema, external tool, assertions Terminal: immediate (test pass/fail)
Pattern B -- Complicated
TRAVERSE (DAG)
Cause-effect discoverable. Traverse node by node. Each node loads its own context. Depth is the node count, discovered retrospectively.
See Section 4 below for per-node detail ↓
Precision: per-node, matched to failure mode Terminal: "can a person act without further analysis?" Socratic questioning per node Working paper (anytime artifact)
Pattern C -- Complex
PROBE
Cause-effect emergent. No analysis will find the answer. Design a probe. Human runs it. Signal comes back. Interpret. Repeat until terminal.
1.Frame what is UNKNOWN (not what to build)
2.Design PROBE: hypothesis, method, signal, cost, reversal, observe-by
3.HANDOFF: human runs probe. LLM cannot.
4.Signal returns → interpret PROBE-RESULT
5.Terminal = decision with reversal conditions. NOT a confident answer.
PROBE artifact (new) PROBE-RESULT artifact (new) Constraint: LLM NEVER produces confident answer for Complex
Pattern D -- Chaotic
STABILIZE
System in crisis. Act first. Don't analyze.
1.ACT: pick most contained action, do it now
2.OBSERVE: what's the state after?
3.RE-CLASSIFY: domain gate runs again
4.Route to appropriate pattern
INCIDENT-RESPONSE.md Mandatory re-classification (new)
Pattern E -- Disorder
DECOMPOSE
Can't classify. Break apart, classify each piece.
1.Decompose into sub-problems
2.Each sub-problem → domain gate independently
3.If child re-enters Disorder → parent decomposition was bad
4.Track decomposition accuracy over time
Decomposition quality tracking (new)

Inside a Complicated Node (DAG Traversal Detail)

This is the most common pattern. Each node in the DAG follows this micro-process. The loop repeats until terminal check passes or appetite budget is exhausted.

Repeat until terminal or budget exhausted
Step A -- Observe
Load Context for THIS Node
Not front-loaded. 2-3 hops of context specific to THIS node's question. Previous context retained but new context scoped to current question.
Classify THIS node's domain (may differ from parent)
Bloom's classifier: Apply? Analyze? Evaluate? Create?

Step F -- Terminal Check
Is This Output Terminal?
Six free checks. Three conditional checks (fire only on failure). All must pass.
1. Output Type
Declare: Decision / Artifact / Probe / Decomposition / Action Items / Intermediate. Action items blocked unless task = planning.
2. "Who Does This?"
Who takes this and acts? Do they need to think first? YES = not terminal. NO = terminal.
3. Convergence Detection
3+ items, verb-led (investigate, analyze, review...), no specific values? Convergence signal.
4. Specificity Threshold
Count concrete nouns: file paths, numbers, names, dates, commands. Must have 3+. (NEW)
5. Output Inversion
Can output be expressed as delta? before→after, old→new? If not, may be too abstract. (NEW)
6. Schema Fill
Can output fill domain schema? Code={file,line,old,new}. Decision={choice,rationale,reversal}. (NEW)
any fail?
7. Beam Search
Branch into 2-3 alternative continuations. Pick the one that reaches terminal. (2-3x cost, this node only) (NEW)
8. Adversarial Check
"Prove this is NOT terminal. Find what the next person would need to figure out." (2x cost) (NEW)
9. Exemplar Compare
Compare against known terminal outputs for this problem type. From TRIAGE history. (NEW)
ALL PASS → TERMINAL. Surface output. Enter Measure.
ANY FAIL → Output becomes input for next node. Loop back to Step A.

Learn
Self-Improving System
Five mechanisms that make the system faster and more accurate over time.
A.RL on depth: after 10+ tasks in category, auto-predict node count. "SEO = 5 nodes."
B.Exemplar library: terminal_reached=yes + accurate=yes → positive exemplar. convergence_detected>0 → negative exemplar.
C.Production rules: locked Clear protocols (10+ uses, 90%+ accuracy) → convert to rule-based. LLM exits entirely.
D.Output shape capture: store not just process but terminal output FORMAT per problem type.
E.Confidence calibration: track LLM confidence vs actual accuracy. Auto-adjust precision enforcement intensity.
RL on depth (new) Exemplar library (new) Production rule conversion (new) Output shape capture (new) Confidence calibration (new) Protocol extraction (existing) Estimation calibration (existing)
