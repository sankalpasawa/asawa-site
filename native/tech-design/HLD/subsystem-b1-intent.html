S1 — Intent (B1)

Per-subsystem High-Level Design, shown from four viewpoints — User · System · AI · Everything. This is the PATTERN SAMPLE for the subsystem-HLD matrix; every other subsystem (S2–S6) follows this exact 5-block shape.

PATTERN SAMPLE — landed 2026-05-27 to validate the 4-viewpoint shape before the other 6 subsystems are generated. Diagrams are ASCII block diagrams (house convention). Canon authority below.

Why 4 viewpoints

One block, four lenses. User = what the operator types/sees. System = runtime mechanics (capture → classify → gate → log → route). AI = the agentic layer (LLM reasoning, HOW-dimension, eval gate, no-fabricate). Everything = the integrated view + how this block connects to the rest of Native. Read top-to-bottom; the 4th view stitches the first 3 together.

Viewpoint 1 — User

What the operator experiences. No syntax, no slash command. If B1 is unsure, it asks one question — it never guesses wrong silently.

 operator:  "remind me to check the deploy at 5pm"
     |
     v
 [ plain words in -- no command, no schema, no form ]
     |
     v
 Native:    "Got it -- TASK, routing to your Action engine.
             Confidence 0.81. Also ping you on Slack at 5pm? (y/n)"
     |
     v
 [ if unclear (conf < 0.6) -> ONE clarifying question ]
 [ never fabricates an intent the operator did not mean ]

Viewpoint 2 — System

Runtime mechanics. Capture is append-only and fsync'd; classification gates on confidence; every turn emits one audit row.

 raw_text --> [Intake Capture] --> .tmp/native-utterance.txt
                    |
                    v
              [Classifier]  (single LLM call)
                    |
                    v
       { intent, confidence, routed_to, clarify }
                    |
                    +--> intake_log.jsonl   (fsync, append-only, ADR-013)
                    |
            conf >= 0.6 ? --no--> [Clarify loop] --back to operator
                    | yes
                    v
       EngineEvent: intake.classified --> routed_to subsystem (B2/B3...)

Contract (frozen before code): in:{raw_text,operator_id,ts} → out:{intent,confidence,routed_to,clarify}. Invariant: never mutates other subsystem state.

Viewpoint 3 — AI

The agentic layer. Classification is one LLM call shaped by the HOW dimensions; the eval gate — not unit tests — is the acceptance bar for an agentic block.

 prompt = system(role + HOW dims) + utterance + trusted-names
     |
     v
 [ LLM classify ] -> intent_type in {ask,task,direction,feedback}
     |               + sub-intents + confidence
     v
 HOW dimension selected:  "decompose" vs "direct" vs "consult"
     |
     v
 EVAL GATE: golden set (50 utterances) >= 90% correct-route
     |        <-- this is the agentic acceptance bar, not unit tests
     v
 low-conf -> clarify   [test-before-conclude: never assert a guess]

Viewpoint 4 — Everything

The three lenses stitched together, plus every connection B1 has to the rest of Native.

 +------------------------ B1 INTENT (integrated) ---------------------+
 | USER:    plain words in        ->  confirm / 1 clarify out          |
 | SYSTEM:  capture -> classify -> conf gate -> log -> route           |
 | AI:      LLM intent + HOW-dim  -> eval gate -> no-fabricate         |
 +--------------------------------------------------------------------+
        |              |               |                |
        v              v               v                v
   runs inside     routes to        gated by        every turn
   NATIVE          B2 Context /      B5 Governance   logged to
   PLATFORM        B3 Action         (authority +    OBSERVABILITY
   (daemon)        by intent_type    hardstops)      (audit + metric)

Connects to: Platform (executes inside the daemon) · B2/B3 (routes by intent_type) · B5 (governance gate before any action fires) · Observability (emits intake.classified + latency metric).
