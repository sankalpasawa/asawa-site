If you only read one section

What is Native? The deployable Sutra plugin clients install. Shipped, it lets one founder + one LLM run a whole company autonomously.

Why does it exist? Today the plugin doesn't yield a working operating layer with one command, companies are built bespoke instead of by primitive composition, and the OS-of-companies governance primitives (identity, authority, tenant boundary, decision provenance, policy-enforcement evidence) are not enforced. See Problem.

Where are we? Architecture is locked after 8 codex review rounds. M1–M3 (scaffold, primitives, laws) shipped. M4 (schemas + extension seams) is next. See Status.

§2The Method — how the architecture was derived

Reusable across all future Sutra plugins. Codex round-3 verdict: ADVISORY.

DocWhat's in it
architecture-method.md v1.1 The reusable rubric: 6 disciplines (Situation / Sovereignty / Invariants / Semantics / Structure / Proof) and the 5-step process (refresh-method → state-problem → trace-gaps → patch-gaps → build)
codex-reviews/arch-method-v1.md Codex r1 / r2 / r3 review of the method itself

The 5 steps — every plugin design follows this sequence

1. Develop / refresh the method itself        (versioned doc + codex challenges)
2. State the problem methodically              (falsifiable PS; no primitives yet)
3. Trace problem → current solution → gaps     (audit grid; codex challenge)
4. Patch gaps                                   (each patch names its discipline)
5. Runtime architecture + build                 (code traces to disciplines)

Between-step gate: surface findings + ASK founder before proceeding.
