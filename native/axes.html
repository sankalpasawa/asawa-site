Axes + families OVERVIEW · sub-page

WORKING DRAFT (2026-06-15). An axis is a dimension you read a piece of work against. Axes are an open set — minted on demand from one primitive (value ↔ axis). What is fixed is the primitive + the families (the slots an axis falls into).

The sorting test

ask of any axis:
  reads the INPUT, fresh every run?        -> SHAPE
  accumulates on the UNIT, across runs?    -> GROW
  gates a transition (auto/ask/deny)?      -> GOVERN
  reads the LINK between two atoms?         -> EDGE
  a finite STOCK the work spends?           -> RESOURCE
  about WHEN / over time?                   -> TIME

One primitive → six families

Familyreads (WHAT)fires (WHEN)page
SHAPEthe input, freshfront — before each runWorkflow
GROWthe accumulated recordover time — after runsEvolution
GOVERNevery transitionthroughoutAuthority + Tenancy
EDGEthe link between atomswired at SHAPE · grown at GROWEdges
RESOURCEa finite stockspent at RUN · reconciled at RECORDResource
TIMEduration+graph / stocks+delayschedule · dynamicsTime
Families = closed skeleton. Axes = open, minted flesh. Solid arrows = the original three families (unit-internal); dashed = the three surfaced this session (between-atoms, stock, time). How a new axis becomes product: axis-productization. The mint/rework rule: open-axis rule.
