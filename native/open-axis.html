The open-axis rule — mint / rework OVERVIEW · sub-page

WORKING DRAFT (2026-06-15). The governance rule that keeps the axis set open without letting it sprawl: users mint axes on the fly; only the core author reworks the families.

Two tiers

The retention outcomes

Minting is cheap, so the gate produces one of five outcomes — not just pass/fail:

OutcomeWhenWhat happens
keeppasses, no overlapproductize via P1–P5
mergeoverlaps an existing axisfold in; keep the better name
renamesame axis, clearer labelalias → canonical
rejectchanges neither what's built nor who-readsdropped as noise — logged, not silent
escalate (family-gap)passes but fits NO familysurfaced to the core author → may trigger a family rework (governed)
Mirrors the two primitives: the Work-Atom is the one doing primitive (everything is it, composed); value↔axis is the one thinking primitive (every axis is it, minted). Only escalate can change the families — and only the core author does that, deliberately.

Working draft · 2026-06-15. The axis set: axes + families. Productizing one: axis-productization.
