§A Idea — Senior Expert product

A.1 Problem statement

Awaiting founder fill. Working frame: the operator (portfolio CEO per CoS §A.2) needs domain-deep work delivered to operator-grade standard inside a narrow specialty (legal review · financial modeling · engineering architecture · product strategy) — but cannot hire a senior expert per company and cannot reach senior-expert quality through generalist CoS work alone. CoS frames + executes operator workflows; Senior Expert OWNS a project inside one domain and brings expert-grade judgment to it.

The gap CoS does not fill: when a project requires sustained expert depth (not just execution), the operator either (a) does it themselves at the expense of other companies, (b) hires a contractor with overhead + onboarding cost, or (c) ships a sub-expert artifact and accepts the quality drop. Senior Expert is the autonomous-expert-on-tap that fills this gap inside Charter authority.

A.2.2 Project-scoped (not turn-scoped) constraint

Hard distinction from CoS: CoS works turn-by-turn — operator says a thing, CoS responds. Senior Expert works project-by-project — operator hands a Charter-scoped project at the start, then sees Senior Expert only at consequential-decision gates + the final deliverable. The operator-experience asymmetry is intentional: CoS is the implementation consultant who is always at the desk; Senior Expert is the contracted specialist who runs the project and reports out.

A.4 Vision

Senior Expert is the second Layer-B Product on Native. Where CoS is the always-on implementation consultant, Senior Expert is the contracted domain specialist — give it a project, it runs the project, surfaces decisions, returns deliverable. Same Charter model. Same operator-in-loop invariant. Different operator-experience shape: project-scoped, not turn-scoped.

The operator's portfolio gains expert depth on demand. Need a contract reviewed? Deploy Senior Expert — Legal under a Charter scoped to that contract; it runs the review, asks operator only on material judgment, returns the redlined draft. Need a board financial model? Deploy Senior Expert — Finance; it builds the model, surfaces assumptions for operator ratification, returns the deck. The operator pays the cognitive cost only at consequential moments.

Vision-state: the portfolio CEO has a CoS deployed continuously + a fleet of Senior Expert instances deployed per active project per domain. Project ends, that Senior Expert instance retires (B5.c audit + B5.d learned persist). New project, new instance (potentially same domain, fresh Charter).

A.7 Task Taxonomy — how Senior Expert maps to Native's T0-T3 tiers

Senior Expert primarily inhabits Native's T3 (Charter) tier — every project deployment IS a Charter materialization. Internally, the Senior Expert decomposes T3 Charter into T0-T2 sub-tasks (which look like CoS turns) but those are platform-internal, not operator-visible.

T1 Multi-actionSub-task internal to project (e.g., "compare 3 contract variants, summarize")No — runs inside the project

Where CoS's primary tier is T1 (multi-action turns), Senior Expert's primary tier is T3 (Charter). Both products use Native's same T0-T3 substrate; the difference is which tier dominates the operator-visible interface.

§Operator surface contract — capability bullets per pillar

What the operator OBSERVES per pillar (Cagan WHAT, not HOW). Engine architecture lives in canon — see §Layer-B claims for the substrate citations.

P1 Operator surface — Charter intake

  • Operator types a project intake utterance (terminal-fluent, one-time setup; zero-terminal during execution per Native §A.2.2).
  • Senior Expert returns a 1-page Charter proposal within <= 1 turn — deliverable shape · consequential-decision list · Authority defaults · projected timeline + cost.
  • Operator ratifies / revises / cancels via a single response.
  • Ratified Charter is the contract — Senior Expert binds to it until P5 (or operator-initiated cancel).

P2 Operator surface — context assembly

  • Operator does not see context assembly happen by default.
  • On query "show me the context used" — operator receives a ranked artifact list with per-source confidence tags.
  • Gaps in context are surfaced explicitly (e.g., "no precedent case found for this clause shape") — not silent gap-filling.

P3 Operator surface — autonomous execution

  • Operator does not see sub-task execution by default — only consequential-decision asks (P4) and progress on query.
  • On query "what's status?" — operator receives a one-paragraph status summary without halting execution.
  • Budget exceed -> execution halts cleanly + operator notified with cost + state-of-progress.
  • Self-review failures (Senior Expert rejects own output below domain-quality threshold) are logged but not surfaced to operator unless retry exhaustion.

P4 Operator surface — operator gate

  • Operator receives a structured consequential-decision ask — named decision · options · recommendation · confidence · supporting context references.
  • Operator ratifies via a single response; can revise · cancel · ask follow-up without losing project state.
  • No time-out auto-execute — Senior Expert waits indefinitely (project Charter dictates retention) for operator response.

P5 Operator surface — delivery

  • Operator receives final deliverable in ratified Charter shape.
  • Plus: "what I did + why" summary, consequential-decision log, cost + time actual vs Charter projection.
  • Audit replay available at any time post-handback (B5.c).
  • Operator does NOT receive: internal sub-task list, Native primitive details, learned-pattern write content (B5.d is system-of-record, not operator-visible by default).

Product-level acceptance

  1. Operator can hand off a domain-instance project and receive an operator-grade deliverable without intervening turn-by-turn.
  2. Operator interacts only at P1 (Charter ratification) + P4 (consequential decisions) + P5 (handback receive) — never at P2/P3 except on explicit progress query.
  3. Consequential-decision count per project <= Charter-projected count (within +- 20% tolerance — TODO ratification).
  4. Operator-grade quality bar — operator does not need to redo the work to ship it (operator-satisfaction signal per §Observability).
  5. Cross-project compounding — second project in same domain runs faster + cheaper + with better Charter shape than first (B5.d learned-pattern effect; TODO measurable threshold).
  6. Hardstop inheritance — all 8 HS-1..HS-8 fire correctly for Senior Expert flows (per §Resilience contract).

Falsification tests (product-level)

  1. Turn-by-turn shadowing test: if operator can shadow Senior Expert turn-by-turn during P3 (vs only at P4 gates), the project-scope distinction from CoS is broken — FAIL.
  2. Generalist test: if Senior Expert can be deployed without a domain-canonical source list, the "expert" claim is hollow — FAIL.
  3. Silent over-run test: if a project exceeds Charter budget without halt + operator notification, autonomy contract is broken — FAIL.
  4. Audit-replay test: if post-handback the operator cannot reconstruct what happened end-to-end via B5.c replay, decision-provenance is broken — FAIL.
  5. Compounding test: if second-project in domain runs at same cost + same Charter quality as first, learned-pattern effect (SN15) is absent — FAIL (acceptable for v1 first deploys; required by v1.5).

§Open questions — Senior Expert (FSE1-FSE7)

Open questions specific to Senior Expert. Pattern follows Native PRD §C.6 FQ1-FQ3 + ADR-020 OQ-020-N for cross-Layer-B questions.

FSE1 — What exactly counts as "consequential" per domain?
Working hypothesis (fabricated): legal = any external-counterparty contact · finance = any spend commit > threshold (operator-set) · engineering = any irreversible architecture commit · product = any external-positioning shift. Needs founder + per-domain expert ratification. Without this list, P4 trigger logic is ambiguous.
FSE2 — Single Charter per project, or multi-project Charter?
v1 = one Charter per project (per A.6 scope). Multi-project Charter (e.g., "review every legal contract Paisa signs in 2026") deferred. Question: when operator wants ongoing-domain-coverage, do they create 1 long-running Charter or N short Charters? Defer ratification to first multi-project operator request.
FSE3 — How does Senior Expert handle out-of-domain questions during a project?
If Senior Expert — Legal during a contract review hits a finance-domain question (e.g., "is this clause's working-capital impact material?"), does it (a) refuse + escalate to operator, (b) delegate to Senior Expert — Finance via DecisionProvenance handoff, (c) attempt + caveat with low-confidence tag? v1 inclines toward (a). Option (b) needs A2A primitive that doesn't fully exist in v1.
FSE4 — When does Senior Expert hand off to a licensed-human professional?
Per A.3 AP5, Senior Expert produces work-product but licensed sign-off belongs to humans (legal opinion · audit · stamped engineering plan). At what step does the handoff happen? At P5 deliverable handback? Earlier? Operator-decision per Charter or domain-rule? TODO: domain-by-domain handoff protocol spec.
FSE5 — Cross-Senior-Expert handoff in v1?
If a project plausibly spans two domains (e.g., M&A involves legal + finance simultaneously), does v1 require operator to deploy two Senior Expert instances and bridge manually, or does v1 ship cross-instance handoff? Inclined toward v1 = manual operator bridge; v1.5 = automated handoff. Cross-references FSE3.
FSE6 — Does Senior Expert get its own Daily Pulse Module integration, or share CoS's?
Daily Pulse aggregates operator-facing metrics. Operator with both CoS + Senior Expert running — single Daily Pulse or per-product Pulse? Inclined toward single Daily Pulse with per-product rows. TODO: Pulse chart-type spec for Layer-B-Product aggregates.
FSE7 — What's the v1 cost ceiling per project?
Multi-day autonomous execution can rack up significant LLM cost. Operator-set Charter budget is the contract (per A.6 + P3 budget halt). But what's the v1 default ceiling per domain instance to prevent first-time-operator runaway? Inclined toward "operator must set explicit budget at P1; no default ceiling". TODO ratification.
