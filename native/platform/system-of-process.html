THE ONLY-SoP-CALLS-HOST RULE — System of Process is the §1.0 locked-schema block that calls the Host (the LLM): the Step primitive (§4.1) is the doc's only LLM-call site — each Step is pre-declared expected output + LLM call OR deterministic action + post-call check — and Steps execute only inside this block. Evidence status (confidence: moderate): this exclusivity is a working rule carried from the founder session of 2026-06-11 (also echoed in sibling drafts); the cited section-1-0-runtime text/SVG never states it explicitly — the Host→Daemon edge is labeled "runs" (downward only) — and ADR-005 only says host-LLM selection is per-workflow. The confirm-and-write-down-or-drop item stays in the founder queue below, verbatim; the same item is carried on platform/host.html.

How a run flows

  1. Orchestration hands in task = process. The daemon substrate dispatches the matching Workflow (Trigger fire: utterance, cron cadence, or event) under an ACTIVE Charter — the Charter reached ACTIVE earlier via operator approval of PROPOSED (§4.2); new tasks arrive only while the Charter is already ACTIVE.
  2. An agent materializes scoped to that Charter, with inherited HOW context from the method-routing bridge.
  3. Steps execute in declared order (the Workflow declares "ordered Steps"; whether execution is strictly one-at-a-time vs parallel-capable is not stated in the doc) — each Step is an LLM call to the Host or a deterministic action, wrapped in pre-declared-output + post-call check — while the typed state envelope carries turn state across pillar stages (intent → context_envelope → decision_trail → outbound → b5_writes), with Native enforcing shape + authority on every handoff.
  4. Before any conclusion, the test-before-conclude gate runs the tier-appropriate pre-declared test: pass routes to PERSISTED (artifact + triple-channel audit written to System of Record, output presented); fail loops back to B3 retry up to N times per Charter, then ESCALATED through the Approval primitive / Authority gate to the operator.
  5. External-effect calls (send / write / delete / pay) exit via connectors only after the Authority gate; connector half-failures push the run into DEGRADED with reconciliation paths.
  6. Hardstops HS-1..HS-8 can drop the runtime into PAUSED at any point.
  7. CSM sits alongside as the lifecycle ledger of which runtime capabilities are live.
  8. Operator feedback post-conclude feeds B5.d learned patterns that adapt future test thresholds.

Position in the first layer

The system as it runs, per the §1.0 locked schema: the operator asks through the UI; the request runs on the Host (Claude CLI — agent runtime + model in one); inside the always-on Daemon, Orchestration translates the request and finds the relevant process to run; the System of Process runs it (this is the runtime), gathering context from the System of Record + the External World and writing output back to the System of Record. Authority + Tenancy gates every access; Host + daemon run on the Compute (host machine). §1.0 places "context-build · verify · connectors" as second-level detail inside this block — verify is the test-before-conclude gate (§4.5) and connector transport is the §5 Connector layer; the SoP-side context-build mechanism is an open gap below.
