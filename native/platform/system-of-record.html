How state flows

  1. Writes enter from System of Process as the per-turn 5-artifact trail: intent record → context manifest → decision provenance → outbound log → substrate write.
  2. The substrate write lands in B5.a active session, plus learned-pattern updates in B5.d.
  3. The four stores B5.a–d are parallel time horizons, not a graduation pipeline — the PERSISTED step writes output to B5.a/b/c/d simultaneously. B5.a (minutes/hours) backs session continuity with handoff of open threads; B5.b portfolio in-flight (hours/days) holds multi-task state across N companies and survives restart.
  4. B5.c accumulates the append-only DecisionProvenance rows forever — 3-channel per ADR-007; HS-4 fires on triple-channel write failure or on any silent overwrite.
  5. B5.d distills learned patterns (months/forever, k=4 emergence). Together with the E.2/E.3 memory layers (working memory, named entities, trusted names, prior intents, ratified directives) and charter preferences, these are what B2 reads at intake and B1 reads for shorthand on future turns.
  6. The versioned artifact store (D.12) cross-links to B5.c: every artifact write produces a DecisionProvenance row, references resolve to exact versions, and changes trigger Connector notifications outward.
  7. Telemetry lands via the JSONL + fsync sink (ADR-013). The §1.0 diagram splits SoR contents as "own | external". Every read and write across all parts is gated by Authority + Tenancy with cross-tenant default-deny.

From record to system — the six mechanisms (ADR-022)

A record that nothing reads back is telemetry, not a system of record. Today Native runs design → execute → record, but the record fails two tests: it is not replayable (state cannot be rebuilt from the log alone) and not regulated (no decision rule reads it in-loop). Five independent disciplines — process mining, transaction processing, event sourcing, operations science, cybernetics — converge on the same shape: a system of work = contracted units + provably-safe composition + an append-only record the system can be rebuilt (replay) or rediscovered (mining) from. ADR-022 adopts six mechanisms, dependency-ordered, that close that loop; this block is the foundation of all of them.

#MechanismTurns the record into…
1SoR truth upgrade (this block)a replayable source of truth — bracket effects, persist LLM output as events, deterministic replay
2Registration-at-birtha where-used index — change impact becomes a query, not archaeology
3Workflow authoring enginea system of work the LLM drafts for any situation (Cynefin-classified, soundness-checked)
4Comparator + admissiona control loop — reference limits + WIP cap read the record in-loop
5The miner (loop closes here)organic growth — mine the record to propose extraction/revision/retirement
6Industry packsany industry — templates + schemas + limits; the engine stays domain-free

Mechanism #1 lives in THIS block and gates the rest (#4 comparator and #5 miner cannot read what is not durably recorded). Canon (linked, never copied — D54): sutra/os/decisions/ADR-022 · research: holding/research/2026-06-12-unit-work-record-science.md.
