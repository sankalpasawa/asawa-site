The one story

One company, one thread. A digital lending company arrives with nothing; five stages later it runs itself. Each stage begins from what the previous stage created — that chain IS the model working. Details live in the concept PRDs and the implementation tab; this page is deliberately small.

Stage 1 — the company arrives, its Systems are minted

The operator says "onboard my lending company" and names four departments. That is all. The model mints each department as a standing system — Origination, Underwriting, Servicing/Collections, Compliance — each born with its charter and five internal-system slots already attached, empty by design (pre-provisioning: nothing will ever grow undefined). Nothing runs yet; the company now has addresses.

Created: 4 standing systems → stored: user-kit/domains/ + user-kit/charters/. Slot format: TODO(founder).

Stage 2 — the first Workflow is written into one of those systems

Now that Underwriting exists as an address, the operator authors its first work: "verify KYC for applicants." The intent is shaped into three atoms — fetch documents, bureau check, verdict — each with one goal and one verify, composed as W-kyc-verify. It is a written blueprint on the shelf of the system stage 1 created. Still nothing has run. Post-sitting note: this authoring flow runs as a Builder workflow — the ruled A13 lifecycle (validate → construct → judge → verify → PROPOSE → APPROVE, gated → register) owns how things get created.

Created: 1 workflow blueprint → stored: template shelf (OPEN). Its atoms carry goal + verify from birth.

Stage 3 — the blueprint runs, and an Engine comes alive

A nightly trigger fires the reconcile blueprint written the same way in Servicing. On run 1 an Engine is born with an empty record; by run 50 it has learned the ledger's normal variance and behaves differently — the same blueprint, now lived-in. This is the written→grown move: stage 2 wrote it, stage 3 grows it.

Created: a growing record slice → stored: atom ledger + record. Learned-patterns store: TODO(founder). Outcomes beyond the drawn pass-path: bounded retries, then escalation to a human with full attempt history (PF-20, RULED); the uniform outcome vocabulary pass / fail-retry / fail-escalate / blocked is DIRECTED at A14, not yet ruled.

Stage 4 — work crosses the systems, a Shadow System is born

An RBI audit needs evidence from ALL FOUR systems stage 1 minted — no single one owns it. The standing systems are not touched. Instead a shadow system is created: a structured overlay with its own glue engine and its own charter (the cross-cutting audit rules), pulling evidence across through edges. When the audit files, it retires; anything worth keeping codifies back into the standing charters.

Created: 1 shadow system (temporary) → its charter + evidence rows; standing systems unchanged.

Stage 5 — the record earns growth

The engine from stage 3 has now produced evidence: one deterministic step ran 40 times with near-zero variance. The adaptation glue proposes hardening it from an LLM call to code; the operator approves at a gate; only the atom's HOW slot changes. Cheaper runs, same goal, same verify. The loop closes: what stage 2 wrote and stage 3 grew, stage 5 improves — and the improved system is what tomorrow's stage 1 intent arrives into.

Created: 1 approved promotion → stored: proposal + approval rows; the atom's HOW updated (C0→C1).
