The Type System RULED · A17+A18

Work-order header

idband / parentstatusversionowner
platform-model-type-systemPLATFORM / platform-the-modelRULED (A17+A18, sitting concluded 2026-08-17)v1claude

The founder rule: for any content there has to be structure. Every piece of content in Native — a rule, a need, a verify check, a workflow, a charter — has a template; every template has a shipped default; every nesting boundary has a contract. Four layers, applied to every primitive.

Epistemic status: RULED at the 2026-08-17 sitting (sheet §11, Type system + Evolution rows). A17 ruled with refinements: the 4 layer names stand; the kernel is a closed CORE plus namespaced extension slots; Workflow takes the first base/child split (superseding the Charter-first recommendation, s7). A18 ruled: the 10-point protocol; the marketplace owns the repository. Census-grounded (59 sites read, 11 already carry the full pattern), dual-AI reviewed (codex + deepseek). Canon ADRs at S7 (one ADR per decision, D67).

s1 · The four layers

The product sentence: Native ships Standard Templates; each org tunes Local Templates; Interfaces keep nested systems compatible; live work runs as Instances.

s2 · What each layer is

LayerWho writes itWhere it livesChanges how often
Standard TemplateThe core OS (fleet repository)L0 — plugin-shippedVersioned releases (semver)
Local TemplateThe org (or its builder engine)L2 — org-local custodyFreely, within the Interface
InterfaceThe core OS, conservativelyWith the Standard TemplateRarely; breaking = migration protocol
InstanceThe runtimeThe record (append-only)Every run

s3 · One kernel, many families

Both AI reviewers converged against one universal schema for all primitives ("key-value soup that cannot enforce real invariants"). Instead:

PartContent
Kernel envelope (every primitive carries it)RULED shape (sheet §11, Type system): a closed CORE plus namespaced extension slots — nothing loose outside a slot. The 8 fields proposed as the census input (identity · semver · ownership · lifecycle · dependencies · contract refs · record-slice refs · provenance) fed the ruling; the exact closed CORE list is fixed on the sheet (A17-2), not here
Type families (one per primitive)Work-Atom family (goal + ONE verify) · Workflow family · Charter family · needs[] family (the six need types — first NEW family to build) · Event family · Engine + System (no primitive spec yet — T6 finding G12)

s4 · The Interface contract

MUST pinMust NOT pin
stable id + semver · primitive kind · required inputs/outputs · event names + payload shape · lifecycle states · verify contract (what is proven, by whom, evidence type) · authority bounds · declared needs[] · failure/retry behavior · record-slice obligations · conformance testsimplementation · prompt/UI wording · local default values · internal steps · stricter-but-compatible child constraints · optimization strategy
Codex: "The contract defines the shape of trust, not the whole behavior." DeepSeek’s runtime warning: grown Engines deviate from declared Interfaces BY DESIGN — so conformance is a continuous runtime verify on the engine’s record slice, not a deploy-time stamp.

s6 · The evolution protocol (A18)

The D38 promotion ladder is the channel; A18 adds what makes it safe at 100 orgs: semver + change classes, conformance tests shipped with every version, automatic child-diffing, migration plans generated before promotion (hard rule: no base change lands without a child migration story), deprecation windows, canary rollout, and a migration assistant — without which divergent orgs become permanent forks.
