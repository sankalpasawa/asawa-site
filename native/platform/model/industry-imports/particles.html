F-PRT-03 Particle-patch unit (FRAGO for in-flight atoms)ADAPTEffort LTODO

SourceMission command FRAGO — https://armyopordshell.com/2025/04/25/introduction-to-the-5-paragraph-army-operations-order/
What industry runsA FRAGO is a delta-only amendment issued against a live order: it changes only the fields that changed, never reissues the whole order, and is itself a numbered, logged unit. The military ran in-flight amendment at scale for a century.
How it fits NativeNEW: an amend operation on the Work-Atom lifecycle (Authored -> Run -> Verify loop on particles.html s5). Attaches to holding/bin/sutra-atom as a new subcommand plus an append-only amendments[] field in atom.json, and must reconcile with the DISPATCH rule that the envelope is FROZEN at bind — an amendment forces an audited re-bind via sutra-dispatch, never a silent mutation of the live envelope.
Build sketch
  1. Add append-only amendments: [{seq, ts, field, old, new, author, reason}] to atom.json.
  2. Implement sutra-atom amend --atom-id <id> --field constraints|context --new <json> --reason <text>: appends the row, never rewrites prior particle values in place.
  3. Wire the dispatch side: an amendment invalidates the frozen envelope, requiring a fresh sutra-dispatch bind with the amended TOUCHES/constraints; dispatch-gate.sh rejects mutations under a stale envelope hash.
  4. Append an atom-ledger row per amendment (audit trail); block goal amendment entirely — one goal + ONE verify is the atom's identity, so a changed goal = abandon + new atom.
  5. Lending example to test with: mid-run W-disburse-loan atom gets constraint patch 'daily disbursal cap lowered by treasury' without reissuing the atom.
Depends onFounder ruling on the amendable set (goal excluded per A1-ext identity); interacts with the DISPATCH envelope-freeze contract; sibling of F-CHR-10 (engine-grain FRAGO) — dedupe at synthesis.
Decision needed (founder)Which particles are amendable in-flight — constraints and context only, or HOW too?
