F-ASY-01 VSM failure-signature diagnostic for sick systemsREUSE-AS-ISEffort STODO

SourceViable System Model (Beer) — https://en.wikipedia.org/wiki/Viable_system_model
What industry runsVSM mandates the same five metasystem functions (S2 coordination, S3 priority, S3* audit, S4 adaptation, S5 identity) at every recursion level, and catalogs the failure signature when each is absent: peer units colliding = no S2; resource chaos = no S3; management believing its own reports = no S3*; no adaptation = no S4; identity drift = no S5. Industry converged on pre-provisioned glue three independent times (VSM, SAFe cadence events, ICS role structure).
How it fits NativeValidates `assembly.internal_system_slots` (the 5 hardcoded slots) exactly as ruled — no redesign. The import is the diagnostic: the failure-signature table becomes the content of the DEFERRED s7 item 'Maturation S2-S5 detector signatures' on assembly-system.html — the audit glue engine maps observed symptoms to the absent/weak glue engine. NEW: detector-signature lookup table, attaches to the audit engine slot of the Internal System.
Build sketch
  1. Add the 5-row failure-signature table (symptom -> absent glue engine) to assembly-system.html s2 and internal-system.html, sourced to VSM.
  2. Write the detector spec: the audit glue engine maps observed symptoms (e.g. two engines contending on one store, R12 = coordination weak) to the table and appends a named diagnosis row to its record slice.
  3. Resolve the DEFERRED 'Maturation S2-S5 detector signatures' open question in DESIGN-DECISION-SHEET.md by pointing it at this table.
  4. Dry-run the diagnostic against the two real glue proofs (daily-governance-audit.sh; _sidebar.py + _manifest-check.py): confirm each maps to exactly one signature row.
Depends onnone
Decision needed (founder)Should a detector firing auto-open a BuildAtom to staff the missing glue engine, or only log the diagnosis?

SourceVSM algedonic channel / Project Cybersyn — https://en.wikipedia.org/wiki/Project_Cybersyn
What industry runsVSM's algedonic channel is a pain signal that bypasses the management hierarchy when a lower level fails to self-correct within a time budget; Cybersyn ran it at national scale on telex. Each recursion level gets an autonomy window T to fix its own deviation before the signal automatically escalates one level.
How it fits NativeNEW: standing Charter rule type `autonomy_window` ({level, budget T, escalate_to}) attaching to `system.charter`; the coordination glue engine owns the timer and fires the existing `sutra-dispatch escalate` path (`holding/bin/sutra-dispatch`, audited, max 2) on expiry. Generalizes today's per-unit ad-hoc escalate into standing composition infrastructure.
Build sketch
  1. Define rule type `autonomy_window: {level, budget, escalate_to}` in the charter rule-type registry draft.
  2. Add the timer duty to the coordination glue slot spec: on a deviation signal start T; on expiry without a close/fix row in the record slice, run `holding/bin/sutra-dispatch escalate --trigger autonomy-window-expired`.
  3. Append every bypass to the audit engine's record slice via the wdp-evidence append pattern so escalations are on the record.
  4. Pick pilot values on the lending example: a W-emi-reconcile deviation gets T=4h at engine level before escalating to the Servicing system.

F-ASY-05 Typed interaction modes on every channel (TT 3 modes)REUSE-AS-ISEffort STODO

SourceTeam Topologies interaction modes — https://teamtopologies.com/key-concepts
What industry runsTeam Topologies gives every inter-team channel exactly one of three interaction modes — collaboration (high bandwidth, short discovery), x-as-a-service (defined interface, long-lived), facilitating (competence transfer, temporary) — plus an expected duration. Modes are expected to shift (collaboration -> x-as-a-service) as interfaces stabilize.
How it fits NativeLands directly on `assembly.edges`. Today an edge carries one of three STRUCTURAL types (handoff / shared-resource / must-cohere, assembly-system.html s2); TT adds an orthogonal COUPLING-mode label + `expected_duration` on the same edge entry. The coordination glue engine (owner of who-may-call-whom in `system.state`) reads the mode. The report reconciles this row as the home for typed-edge label vocabulary.
Build sketch
  1. Add `mode ∈ {collaboration, x-as-a-service, facilitating}` + `expected_duration` fields to the edge entry in the assembly serialization schema draft.
  2. Update the `assembly.edges` row in the assembly-system.html s5 data-model table with the two new fields.
  3. Type the lending example's edges: Origination -> KYC platform = x-as-a-service (long-lived); disbursal + payment-gateway launch pairing = collaboration (short).
  4. Add a coordination-engine duty: flag edges past expected_duration still in collaboration mode — TT's mode-shift expectation made checkable.

SourceIncident Command System (FIRESCOPE) — https://firescope.caloes.ca.gov/SiteCollectionDocuments/ICS%20History%20and%20Progression.pdf
What industry runsICS forces overlay existence with numeric declaration triggers (second agency involved / customer-visible / unsolved past a time bound), scales which role seats activate via a severity dial, and inverts rank for the overlay's lifetime — the Incident Commander outranks the CEO until close. 50 years of fire-line plus SRE/PagerDuty evidence.
How it fits NativeMakes X4's shadow clause executable instead of descriptive. Three NEW charter rule types in the shadow-system section of the charter content model: (a) `spawn-shadow-on(predicates)` numeric auto-spawn triggers; (b) a SEV input on the shadow Assembly template selecting WHICH of the 5 `assembly.internal_system_slots` instantiate (today all-or-nothing); (c) `rank_inversion(role, scope=shadow lifetime)` with automatic expiry at close, logged by the audit engine. Home rows for the pieces are F-SHD-01/-02/-03 and F-INS-07/-10; this card is their assembly-grain composition.
Build sketch
  1. Define the three rule types in the charter rule-type registry draft: spawn predicate set, sev-to-slot activation map, rank_inversion with expiry.
  2. Add a `sev` parameter to the shadow Assembly template shape: SEV-4 instantiates coordination+audit slots only; SEV-1 instantiates all five.
  3. Wire spawn predicates to record-slice events: '2+ standing systems touched by one unit' readable from dispatch envelopes; '>1h unsolved' from atom open timestamps.
  4. Rule the expiry mechanics: the shadow close event auto-revokes the inversion; the audit engine appends the revocation row.
  5. Worked example: the RBI-audit mandate spans all four lending standing systems -> predicate fires -> SEV-2 shadow spawns with coordination/audit/identity slots and inverted authority over reporting cadence until the filing date.
