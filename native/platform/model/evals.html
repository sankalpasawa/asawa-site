Evals — the Eval Engine GLUE ENGINE · AUDIT TYPE

Every Work-Atom writes down its check before the work. The Eval Engine keeps those checks, re-runs all of them forever, and watches the score. DRAFT

s1. Purpose

Work is checked once, at close — then the check is never read again. So decay is invisible, changes are untested against the past, and the judges are unjudged. The Eval Engine makes four promises: nothing rots silently; change without fear; a quality number that moves; trustworthy judges. Ruled at ADR-031 (Accepted 2026-08-07).

s2. How it works

PieceWhat it is
Casea closed Work-Atom: its goal + its pre-declared runnable check
Packcurated set of cases, tagged: decay-sensitive (scored) · frozen (history) · env-bound · sandbox-required (excluded until sandboxed)
Runbatch re-execution of every case's check against the system as it is NOW — through the shared verify-runner, the same semantics as atom close
Scorecardpass % + per-tag breakdown + a receipt per case; exclusions always printed
Diffrun vs run: which cases flipped (regression / recovery / added / removed)
Judge lanean AI grader reads goal + check and grades whether the check genuinely tests the goal — grade plus written reasoning kept
The integration rule: eval replay and sutra-atom close run the same check the same way. One check executor, two callers.

s3. Product use cases

#ActorScenario
1Foundernightly eval section in the governance audit names each decayed atom, its check, and the day it flipped
2Claude sessionbefore a workflow change ships, run the pack touching the same files; a regression stops the change
3Fleet companytheir atoms accrue into their own pack; the same nightly score for their own work (post plugin ship)

s4. Operational scenarios

ScenarioBehavior
Check fails at nightWARN decay row into findings; triaged next morning
Runner itself crashessingle CRITICAL eval-infra row — infra never masquerades as decay
Stale casetagged frozen at curation; excluded from score, kept as history
Kill-switch~/.eval-nightly-disabled stops nightly runs, nothing else

s5. Contract

  • Read-only: the engine reads records and repo state; it never mutates work engines.
  • Same check: replay executes the atom's declared check via the shared verify-runner.
  • Receipts: every score keeps per-case evidence; judge grades keep written reasoning.
  • Honest score: excluded/frozen/skipped counts always print with the score.

s6. Implementation today

Live 2026-08-07: exporter + packs + decay task (Inspect AI, model none) + nightly launchd job + normalized findings. First run: 187 cases packed, 132 scored, 122 pass / 10 real decay findings (one deleted shipped artifact among them). Grader-lane spike (verify-quality judge): GO — 10/10 sampled checks graded WEAK with reasoning, so check-quality debt is now measurable. verify-runner promoted to the plugin at v2.72.0.
Deferred, recorded: docker sandbox for sandbox-required cases (docker absent on host); judge calibration vs 20 founder-labeled cases; sutra-atom close wiring onto verify-runner (gated on atom test suite).
