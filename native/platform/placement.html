Placement — every unit of work gets an address PLATFORM · zoom 3

Where this page sits — the company map (highlight moves, map never changes)

Same map on every page; only the highlight moves. Placement's governance home is the Authority + Tenancy wrap — it decides which Domain and Charter authorise a unit of work. Its persistence projects onto System of Record. Up = abstract (WHY) · down = concrete (HOW). Purple dashed border = the governance wrap (governance/). Full frozen reference: master.

Every unit of work carries exactly one resolvable address — one Domain, one Charter — stamped before the work executes, without ever stopping the operator.The 35-step process is complete end to end; every step names its input→output, its failure mode, and the canon invariant it satisfies; no step depends on operator ratification.

This page's own diagram

Solid boxes = internal parts of the placement pipeline. Dashed boxes = neighbours (Host/Orchestration upstream, work execution downstream) whose internals live on their own pages. MINT is the only conditional stage — the dashed diagonal is the matched path that skips it entirely.

The problem this closes

#Defect in canon before ADR-028Consequence
1B3 bound only Workflows to Domains, and only at registration timeInline utterances, ad-hoc edits and commits had no address at all. MECE covered the taxonomy but not the activity
2B3 specified its check against Workflow.domain_id — a field absent from the Workflow primitiveThe MECE check was written against a phantom and could never have run
3B3 deferred Domain auto-creation to ADR-010, which proposes Workflows, never DomainsThe hole had no owner. Nothing in Native could create a Domain from emergent work
4Charter→Domain described three incompatible ways across charter.md, B4 and C2, and stored nowhere"Which Domain does this Charter serve" required inference from ACL at read time
5P5 asserted MECE; nothing computed itThe guarantee was rhetorical — no runnable falsification

Two nouns, one address

DomainCharter
What it isA place — holds the information, skills and context for one areaA vehicle — the thing that runs, made of Workflows
ShapeMECE tree, arbitrary nesting, no overlap, no catch-allLives inside exactly one Domain; a Domain hosts many
Identityref — stable, assigned once, never changesC-<hash> — content-addressed, immutable
Positionid — D3.D2.D7, positional, changes on restructure, display only—
Who creates itSystem, automaticallySystem, automatically (stub)
Identity is not position. The dotted D3.D2.D7 encodes where a node sits, so re-parenting rewrites it and every descendant's. Everything that must survive restructure — Placement rows, Charter home, external references — keys on ref. The dotted path is recomputed at render time. Without this split, one MOVE would re-mint every Placement in the moved subtree.
