How state flows

  1. Writes enter from System of Process as the per-turn 5-artifact trail: intent record → context manifest → decision provenance → outbound log → substrate write.
  2. The substrate write lands in B5.a active session, plus learned-pattern updates in B5.d.
  3. The four stores B5.a–d are parallel time horizons, not a graduation pipeline — the PERSISTED step writes output to B5.a/b/c/d simultaneously. B5.a (minutes/hours) backs session continuity with handoff of open threads; B5.b portfolio in-flight (hours/days) holds multi-task state across N companies and survives restart.
  4. B5.c accumulates the append-only DecisionProvenance rows forever — 3-channel per ADR-007; HS-4 fires on triple-channel write failure or on any silent overwrite.
  5. B5.d distills learned patterns (months/forever, k=4 emergence). Together with the E.2/E.3 memory layers (working memory, named entities, trusted names, prior intents, ratified directives) and charter preferences, these are what B2 reads at intake and B1 reads for shorthand on future turns.
  6. The versioned artifact store (D.12) cross-links to B5.c: every artifact write produces a DecisionProvenance row, references resolve to exact versions, and changes trigger Connector notifications outward.
  7. Telemetry lands via the JSONL + fsync sink (ADR-013). The §1.0 diagram splits SoR contents as "own | external". Every read and write across all parts is gated by Authority + Tenancy with cross-tenant default-deny.

Per-turn 5-artifact audit trail Every Native turn produces 5 stored artifacts: 1. intent record (B1) · 2. context manifest with ranked artifact list + what was dropped (B2) · 3. decision provenance with phases + factors + authority verdict + output (B3) · 4. outbound log (B4, if comms) · 5. substrate write (B5: active-session ref + learned-pattern updates). section-7-2-audit
Versioned artifact store (D.12 lifecycle integrity) Append-not-overwrite: every change adds a version, prior version stays accessible; reference-with-version (artifact@v3 resolves exactly); metadata (owner, version, source-of-truth status) travels with the artifact; every artifact write produces a DecisionProvenance row linking creator-Charter + reason + diff-from-prior. Zero silent overwrites (HS-4 fires on version-bump-less replace). d12-artifact-governance
DecisionProvenance row schema (ADR-007) 3-channel append-only audit row per decision (ratified). HS-4 fires on triple-channel write failure (per B5 acceptance). section-12-1-adr-table
