Terminal Check -- 9-Layer Gate

Runs at every node boundary. Layers 1-6 are free. Layers 7-9 fire only on failure.

Free Checks (always run)
1. Output Type Declaration
Must declare: Decision / Artifact / Probe / Decomposition / Action Items / Intermediate. Action Items BLOCKED unless task = planning task.
2. "Who Does This Next?"
Who takes this output and acts? Do they need to think/analyze/decide before acting? YES = not terminal. NO = terminal.
3. Convergence Detection
3+ items, verb-led (investigate, analyze, review...), no specific values? Convergence signal fired.
4. Specificity Threshold (NEW)
Count concrete nouns: file paths, numbers, names, dates, URLs, commands. Must have 3+. Below = too abstract.
5. Output Inversion (NEW)
Can output be expressed as delta? before>after, old>new, current>changed. If not, may be too abstract to be terminal.
6. Schema Fill (NEW)
Can output fill domain-specific schema? Code={file,line,old,new}. Decision={choice,rationale,reversal}. Probe={hypothesis,method,signal}.
any of 1-6 fail?
Conditional Checks (fire only on failure above)
7. Beam Search (NEW)
Branch into 2-3 alternative continuations. Pick the one that reaches terminal. 2-3x cost for this node only.
8. Adversarial Check (NEW)
"Try to prove this output is NOT terminal. Find what the next person would need to figure out." 2x cost for this node only.
9. Exemplar Compare (NEW)
Compare against known terminal outputs for this problem type from TRIAGE history. Available after 10+ solved tasks in category.
ALL PASS > TERMINAL. Exit node loop. Enter Phase 7 (Output Gate). ANY FAIL > NOT TERMINAL. Output becomes input for next node.

Five Response Patterns

Each Cynefin domain gets a fundamentally different execution shape.

A
Clear > ENCODE
Cause-effect known. Pattern exists. LLM encodes into mechanism. Mechanism runs.
1.Load existing pattern from protocol store (os/protocols/)
2.Pick mechanism: code / SQL / spreadsheet / checklist / direct execution
3.LLM designs mechanism (function + tests + assertions)
4.Mechanism runs. LLM NOT in execution loop.
5.Verify: test pass/fail, schema validation (immediate)
6.If domain shifts mid-execution (node needs judgment): pause, reclassify as Complicated, resolve, re-enter

B
Complicated > TRAVERSE (DAG)
Cause-effect discoverable. Node-by-node traversal. See "Inside a Node" tab for full detail.
Per-node loop: Observe > Shape > Plan > Execute > Precision > Terminal Check
Context per node (2-3 hops). Socratic questioning. One branch per node. Working paper.
Depth = node count, discovered retrospectively in TRIAGE.
TASK-LIFECYCLE.md
ESTIMATION-ENGINE.md
All templates
Socratic + MCTS + Bloom's + Working paper + Precision catalog
C
Complex > PROBE
Cause-effect emergent. No analysis will find the answer. Design probe. Human runs it. Interpret signal.
1.Frame what is UNKNOWN (not what to build)
2.Design PROBE: hypothesis / method / signal / cost / reversal / observe-by
3.HANDOFF to human (LLM cannot run probes). Clear instructions.
4.Signal returns > interpret PROBE-RESULT: signal_observed / hypothesis_confirmed / inference / next_action
5.Terminal = decision with reversal conditions. NEVER a confident answer.
6.Not terminal? Design next probe. Loop.

Chaotic > STABILIZE
1.ACT first. Don't analyze. Pick most contained action.
2.OBSERVE state after stabilization.
3.RE-CLASSIFY via domain gate (mandatory).
4.Route to appropriate pattern.

3.If child re-enters Disorder: bad decomposition
