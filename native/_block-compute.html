Internal flow (as documented)

The doc draws Compute as one undivided dashed box at the base of the §1.0 diagram; all internal structure above is assembled from the daemon’s documented footprint in §4.0, not from a Compute-section decomposition. On the host machine, the OS process facility runs the single per-operator daemon process; the cron facility feeds the process facility twice (as a START trigger alongside plugin launch and cold boot, and as recurring cadence ticks that the daemon turns into Workflow dispatches per ADR-017); the process facility reads and writes the per-operator filesystem state at ~/.sutra-native/ continuously (audit JSONL writes + user-kit markdown while RUNNING) and reads it back on RESTART (state restored from user-kit + decision-provenance log, surviving plugin re-exec without state loss).

The Host (Claude CLI) executes on the same machine, but the doc draws no compute-internal edge between Host and the daemon at this layer — their interaction is modeled above Compute in the §1.0 stack. The deferred cloud-hosted variant (v2+) would replace the operator-local machine entirely, with no schema impact described yet.

Open / gaps — questions for the founder

  • No hardware/OS requirements for Compute anywhere in the doc (supported OS, CPU/memory/disk minimums) — what does an operator’s machine need?
  • Is Host + Daemon co-location on one machine a hard constraint, or can they split across machines? §1.0 only says both “run on the Compute”.
  • Compute failure semantics beyond “cold boot → START”: what happens to in-flight Workflow executions when the machine sleeps, crashes, or loses power mid-run?
  • Cloud-hosted channel (§1.4.5) defers managed compute to v2+ but never says how the §1.0 schema changes when compute is not operator-local — where does the Host (Claude CLI) run in that channel?
  • No resource governance on the operator’s machine: nothing caps daemon CPU/disk usage or defines retention/rotation for decision-provenance.jsonl and native.log growth.
  • Authority + Tenancy “gates every access” wraps the Compute box in the diagram, but no compute-level enforcement mechanism (disk encryption, key storage location, local access control) is named.
