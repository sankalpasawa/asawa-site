The four types — what is missing

Native already reads a unit of work two ways: the Cynefin lens judges causality, and workflow-type resolution (ADR-026) judges process shape. Neither answers the question that decides the first move — what is missing? These four types answer only that.

How to read the names. The first word is the question; the second word is the answer. Known unknowns = you hold the question, not the answer. Unknown knowns = the answer is in the building, nobody asked. Unknown unknowns = neither. Known knowns = both.

TypeCell + glossMissingFirst moveClosable today?
T1known knowns · we know it, we do it by handoperationalisationauthor or reuse the workflow; run it on the RUN surface with steps, approvals, audityes
T2known unknowns · we know what we don’t knowthe answera bounded experiment whose purpose is to measurepartial — the machine runs and records the test; a human still chooses what to test
T3unknown knowns · we have it, we haven’t worked it outthe workflowsurface the pattern, then propose a workflow for operator approvalonly inside ADR-010’s unmatched-work detector — general record mining is not claimed
T4unknown unknowns · we don’t know what we don’t knowthe questionwatch weak signals on a cadence; output is a surfaced question, which converts the unit to T2sensing only — never claim T4 is solved

Four different economics

Each type carries a different kind of cost, which is why one management toolkit cannot serve all four. Efficiency programmes operate on T1; applied to T4 they remove the slack T4 requires.

TypeCost typeWhat good management looks likeBudget line in a normal company
T1labour cost — visible, reduciblestandardise, then operationaliseheadcount + tooling
T2variance cost — wrong bets, missed forecastsbuy information cheaply before committingcontingency reserve, experiment budget
T3opportunity cost — already paid for, never harvestedanalyse what is already held; write it downnone — no line item, no owner
T4existential cost — rare, severeslack and optionality, not better forecastsmanagement reserve, insurance

Why the two low-awareness rows have no owner. Reporting systems can only report what somebody thought to measure, so T3 and T4 are structurally invisible to the P&L, the KPI dashboard and the risk register alike. That is not an oversight in any particular company; it is a property of instrumentation.

The conversions — and the decay

Type is not a permanent label. Conversion is the work (ADR-030 Decision 4).

ConversionWhat buys it
T4 → T2attention: cadence watching of weak signals
T2 → T1a bounded experiment whose result is written down
T3 → T1a surfaced pattern the operator approves as a workflow
T1 → T4nothing — this direction happens by default
Decay is an interpretive rule, not a state machine (ADR-030 Decision 5). Canon defines no T1 lifecycle state and no automatic transition, and this page does not invent one. The claim is narrower: thresholds, rules and counterparty behaviour drift, so a workflow that has run unexamined for a long time should be read as possibly blind rather than known. Re-verification against the record is the counter. Any page presenting these four types as a one-way ratchet into T1 is misleading.

Three lenses, one unit — none substitutes for another

LensQuestion it answersSource
Problem type (T1–T4)what is missing?ADR-030 (this page)
Cynefin lenshow does cause relate to effect?core:flow step [4]
Workflow typewhat shape of process fits?ADR-026

All three may be stated for the same unit. The types are exhaustive by construction — two binary axes — but they are a lens for reading a unit, not an enum any component may branch on until an ADR wires them (ADR-027 keeps the axis set open).

Status of this page

Open gaps — founder queue

  • Not wired. The resolver does not read problem type. Wiring it into core:flow step [1] alongside the Cynefin lens — and deciding whether the type is operator-declared, inferred, or both — is open (ADR-030 open item 1).
  • T3 scope. Whether pattern surfacing extends beyond ADR-010’s unmatched-work detector is undecided. If it does, it needs its own ADR, a per-tenant compute budget and a tenancy review — the record is tenant data (open item 2).
  • T2 evidence. Where a measurement is stored and what evidence closes an experiment is undefined. DecisionProvenance (ADR-007) records decisions with fixed scopes; it is not a measurement store, so citing it for experiment results would be a category error (open item 3).
  • T4 probe object. Whether a “standing probe” is an ordinary Workflow with a TriggerSpec is undecided; today the phrase describes intent, not a defined object (open item 4).

Children / downstream

  • None — leaf page. Downstream consumers are the resolver (unwired) and any operator-facing surface that names a type.
