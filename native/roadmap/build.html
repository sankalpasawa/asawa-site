How we build it out — core platform → downstream → CoS (one roadmap + timeline)

We build the core of the platform engine first, then gradually build downstream pieces, until we reach the CoS — the Chief-of-Staff product the operator actually uses. Stage names are the Native canon's own terms (platform blocks, the six surfaces, the CoS pillars B1–B5). The only version numbers are the releases v1 / v2 / v3 from §C.1 — there is no separate build-numbering. Per-stage detail lands subsequently; this is the readable map.

CoS appears twice on purpose. Canon puts the 5 CoS pillars in v1 (terminal), so a thin CoS rides on the core early; the full CoS is reached only after the downstream platform matures (tenancy · connectors · UI) by v3/GA.

Three lanes: CORE PLATFORM (build first) · DOWNSTREAM PLATFORM (gradually) · CoS PRODUCT (the destination). Timeline = rough weeks from kickoff (estimates). Dashed flags = release cuts v1 / v2 / v3.
