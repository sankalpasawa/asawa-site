cap/116 — PROTO-006 process-discipline routing ladder SHIPPED (policy-visible)

Shipped today (distilled): Production ships PROTO-006 in two coupled forms — a constitutional protocol (PROTOCOLS.md L170-178, the merged Process-Is-Default + Escalate-Before-Violating original) and a fleet schema (sutra-defaults.json .process_discipline_proto006, v2.26.0). Both encode the same resolution ladder; this section's ROUTE-I5 invariant is the Native canon port of that ladder.

Behavior contract (verbatim)

When an agent receives a task or cannot complete a required process step: follow the process if it exists; if it cannot be followed, resolve without skipping; if still blocked, STOP and ask the human — never write 'TBD'; doubt about whether to ship routes through dispatcher classification (TYPE/ROUTE) + Depth + BLUEPRINT before acting, with no silent skips; only the named founder override phrases ('skip the process' / 'just do it' / 'skip depth assessment') suspend it.

Redo recipe (Native, verbatim)

Encode in Native as a pre-action policy/hardstop node: trigger conditions + the 3-step resolution ladder (follow -> resolve-without-skipping -> STOP-and-ask-human) + the banned token 'TBD' + the explicit named override phrases. Port the PROTOCOLS.md check text verbatim — it is the constitutional original. Wire it into the workflow engine's pre-action decision points (the schema's applies_to) rather than leaving it memory-only, which is the one production weakness; also resolve the HARD-vs-SOFT label inconsistency between the protocol body and registry row when porting.

dir/D17 — capture ALL founder statements + multi-intent decomposition SHIPPED (substrate) / gap (decomposition)

Shipped today (distilled): Doctrine D17 ("Capture ALL founder statements in rapid succession… Check message queue before responding") ships as a behavioral enforcement row plus the hard substrate capture-prompt.sh (plugin L0 fleet hook, UserPromptSubmit) that losslessly appends every founder prompt to a monthly append-only JSONL. The Orchestration-side multi-intent decomposition step it implies was never built — this is the missing B1 mechanism.

Behavior contract (verbatim)

When a founder turn contains multiple directives, the agent enumerates each statement before acting and count(actions) must cover count(statements); independently, every founder prompt row is persisted to a monthly append-only JSONL regardless of whether it was acted on.

Redo recipe (Native, verbatim)

Two pieces: (1) port capture-prompt.sh near-verbatim as the lossless substrate (Native already has prompt provenance ambitions per D60); (2) implement the missing mechanism — a multi-intent decomposition step in the B1 intent layer that splits one turn into N statements, emits one queued work item per statement, and runs a coverage check (work items >= statements) before the turn closes. Production never built (2); it relied on doctrine + behavioral enumeration, so design the queue contract fresh rather than porting.
