DecisionProvenance — typed audit row primitive (ADR-007 + canon)native-canonDecisionProvenance is Native's typed audit row for every consequential decision — Workflow-level, Step-level, Hook-level, Tenant-level, or Cutover-level; every Workflow/Execution/Hook emits ≥1 row per consequential decision (I-7). Fields per ADR-007/§2.9: id (uuid v4, unique), monotonic ts_ms, agent_identity chain (ADR-015, parent→child), policy_id + policy_version both non-empty (I-9 + I-17; empty either field is a HARD F-8 reject), scope ∈ {WORKFLOW, STEP, HOOK, TENANT, CUTOVER}, outcome ∈ {allow, deny, pause, escalate}, sanitized reason (no colons, no newlines — protects JSONL parsing), and data_refs[] each carrying authoritative_status per ADR-008. PolicyDispatcher.evaluate(scope, evidence) returns the row; UserKit.appendDecisionProvenance fsync-writes it to ~/.sutra-native/user-kit/decision-provenance.jsonl AND to the owning Tenant's audit_log_path when the decision touches a Tenant. Rows are inert immutable records — once persisted they are final, no state transitions. ADR-007's decision rationale: every consequential decision is replayable from a structured row, and policy version drift is detectable (same evidence + different policy_version → different outcome). ADR-007 rejected unstructured log append (loses policy version, fails F-8, blocks replay) and hook-scoped gate-log extension (Workflow/Step/Tenant/Cutover scopes need the same primitive uniformly).sutra/os/native/primitives/decision-provenance.md#purpose

EngineEvent — append-only typed event log with exhaustive 26-type catalognative-canonEngineEvent is Native's append-only typed audit row — one JSONL line per event — forming the complete audit trail for Workflows, Executions, Triggers, approvals, rollbacks, pattern emergence, commitments, and tenant boundary violations. Telemetry sink — fsync'd JSONL append (ADR-013)adr-decisionNative engine MUST persist EngineEvent and DecisionProvenance as fsync'd JSONL append-only files; the H-Sutra event bus follows the same shape. One JSONL line per event/decision, UTF-8, no newline-in-field (sanitized at emit); fsync per append for durability — never lose a row on crash. Stderr beacon fallback when the primary path is unwritable, with dual fallback to /tmp (the HS-4 chain). The pattern detector (ADR-010) reads the log directly — no in-memory cache; restart-safe. Alternatives rejected: in-memory ring buffer (dies on daemon restart — codex P1.2 forced rejection) and SQLite/DB (adds dependency + schema migrations; JSONL won on append-only proof + zero-dep). Consequences: crash-safe and multi-process safe (POSIX append atomicity for short lines); no indexed query — replay is sequential scan, aggregation is downstream tooling; OTel production transport (OS-10) is the next-tier deferral, JSONL stays primary. The second-order draft labels this part "TELEMETRY SINK · ADR-013 · JSONL + fsync · no silent loss".sutra/os/decisions/ADR-013-telemetry-sink-fsync-jsonl.md#decision

construct/os-manifest — versioned should-exist declaration + enforcement loop

Behavior contract: For each client tier (1 governance / 2 product / 3 platform) the manifest declares what SHOULD exist — required files, hooks with registration events, content rules with forbidden-pattern regexes, and pinned version. Verifiers enforce the core invariant DECLARED ⊆ INSTALLED ⊆ REGISTERED structurally (every declared hook must exist on disk, be executable, and be registered in settings.json — checked via jq for a .command field, explicitly rejecting raw path-grep), emitting a DRIFT row for every gap. The manifest's client registry is the single source of which instances get walked — empty-parse fails loud (WARN, exit non-zero), never silently falls back to a hardcoded list; a version bump triggers atomic registry-wide propagation that re-verifies and never half-upgrades. Manifest-vs-source drift (OS-19 class; live specimen marketplace.json 2.35.3 vs plugin.json 2.39.7) is a named, ledger-tracked failure class.

Redo-recipe gist: Define Native's Manifest as a versioned per-scope declaration of which constructs (workflows/gates/hooks/defaults) exist at version N; port verbatim the §7 invariant (declared ⊆ installed ⊆ registered, structural check, DRIFT rows), the fail-loud-on-empty-registry rule, and the atomic-propagation contract (compare pins, upgrade fully or not at all, re-verify); redesign the registry as machine-native JSON from day one (the awk state-machine parser exists only because the registry lived in a markdown table and grew divergent hardcoded fallbacks); gate every release on manifest-validity tests.
