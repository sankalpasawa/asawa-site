How to read this index (and what it deliberately does not do)

This page answers one question: "what is the complete, canonical set of typed things Native works with, and where do I go for each?" It is the table of contents for the data model — a flat, one-row-per-primitive lookup with no schema in it. Each row routes to two homes:

  • Owning part page (column 5) — the engineering page that holds the primitive's mechanism rows: how it is minted, validated, persisted, dispatched. That part page is the one home for those mechanisms (BUILD-PROTOCOL principle 7).
  • Data-model row (column 6) — the sibling cross-cutting data-model view, which carries the full field schema (canon field names + invariant ids), the relationship edges between primitives, and the ExecutionResult lifecycle. That is the design home; this index never restates it.

It deliberately does NOT carry field tables, invariants, relationship edges, or lifecycle states. Those live on data-model.html (assembled once) and in canon (D54). Two boxes, same question → merge: there is exactly one home for each detail, and this index links it (BUILD-PROTOCOL hard rules 3 + 5; principle 6 "earn the box" — the catalog earns its box by being the fast lookup, not a second copy of the model).
