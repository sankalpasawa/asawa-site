§4.5 test-before-conclude gate (accuracy primitive)master-spec'Native does NOT mark a task done before testing the output. Accuracy is a per-workflow KPI. Test happens BEFORE concluding, not after. Output is rejected back to B3 retry if test fails.' Five steps: (1) pre-declare test per tier — T0 grep / file-exists / contract-match; T1 step-by-step verify + final integration check; T2 operator-visible 1-min iteration verification; T3 milestone-gate verification at goal-transition points; (2) B3 produces output (auto-execute path); (3) run the pre-declared test — 'Determinism: same input + same Charter → same expected output shape'; (4) conditional conclude — pass → conclude + write audit row + present to operator; fail → loop to B3 retry (max N retries per Charter), after N failures escalate to operator (Authority gate); (5) post-conclude — operator feedback (drop / accept / refine) becomes test signal for B5.d learned patterns, thresholds adapt per workflow. ADR-011 on_failure policy — closed 5-setadr-decisionADR-011: 'Native engine MUST define step.on_failure as exactly one of {rollback, escalate, pause, abort, continue} — closed 5-set, no extension without ADR.' TriggerSpec primitive + ADR-017 cadence schedulingnative-canonTriggerSpec declares WHEN a Workflow fires: pattern ∈ {preprocessor, observer, gate, fan_out, negotiation} (closed 5-set), a typed predicate (match-all / match-any / cron — never free prose, HARD rejected at mint per ADR-012), target_workflow_id that MUST resolve in the user-kit registry (mint-time HARD reject if unresolved; non-firing if target later deprecated), and an optional cadence object per ADR-017.
