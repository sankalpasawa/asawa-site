Security zoning — the substrate's tenant boundary as one picture

Tenant isolation is the property the matrix flags twice (B5×SoR and B5×A+T both PRIMARY) but never draws as a single boundary. The zone is: the operator's portfolio is one tenant boundary; each company's data, audit log, and replay queries sit inside it; the only legal crossing is an explicit delegates_to edge. The enforcement is split — A+T runs the gate, SoR keeps a per-tenant audit_log_path so a tenant's rows never share a file with another's, and Observability inherits the same deny on audit/replay queries. The Governance cross-cutting view owns the enforcement model for the whole machine; this pillar narrows it to the B5 substrate's round-trip. Default-deny holds at write (HS-3), at read (audit query), and at replay — three surfaces, one boundary.

Open gaps — founder queue

  • B5 Ring-1 surface cells unfilled (founder voice). Problem space (T-G1-14), Need/outcome (T-G1-15), Solution direction (T-G1-16) for B5 are Awaiting founder fill in §2.B B5 — the whole-pillar design above is the Ring-2 contract + Ring-3 mechanism view; the operator-voice Ring-1 stays a founder gap. No fabrication.
  • B5.b portfolio multi-task state machine deferred. The token-budget allocation + multi-thread state machine for the 5 in-flight tasks across N companies is a Phase-2 engineering hard-problem, not yet designed (governance-substrate-design.md / T-G3-05). The round-trip invariants above assume B5.b state survives restart but do not specify the allocation algorithm.
  • HS-4..HS-8 mechanism-pending. HS-4 (audit-unwritable, the fail-closed anchor of I-B5-3) is documented doctrine but the impl-vs-docs audit confirms live detectors do not yet exist in the shipped runtime (master §4.10.1 callout · §10.10). HS-1..HS-3 have partial enforcement. So I-B5-3's fail-closed guarantee is canonical, not yet fully shipped.
  • Cross-process replay deferred (OS-3). The AUDIT surface names cross-process replay as deferred and has no audit_log_write_failed EngineEvent (HS-4 uses a stderr beacon, not an event). I-B5-1's round-trip identity is specified for the single-process replay path; the cross-process case is an open canon gap (sutra/os/native/surfaces/audit.md#integration-points).
  • Latency budget unmeasured per-phase. The ≤30s replay budget (I-B5-4) is a point target; there is no per-phase profiling splitting the SoR scan vs Observability assembly portions, and the <15% governance-overhead budget lacks a computable formula in the shipped runtime (per the SoR/Observability shipped-production dossiers, charter/speed). The budget is asserted, not yet instrumented end-to-end.
