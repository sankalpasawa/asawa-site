How to read this view — one-home discipline

This is a cross-cutting engineering page. The 13 per-part engineering pages (ui, host, …, observability, matrix) each answer "how does THIS part work" and own their mechanism rows. This page answers a different question — "what does the whole system promise on perf / security / accuracy / reliability / cost / resilience" — that no single part page states. Per BUILD-PROTOCOL #7 (one home, cite the rest), every concrete mechanism below is a LINK to its home (a master anchor or a part page), not a copy. Where a target has no home yet, it is logged as an open gap rather than invented (no fabrication).

Native's performance promise is operator-perceived, not raw machine latency: the system must let the operator decide fast (<30s), replay history fast (≤30s/day), and never let governance machinery eat more than a quarter of the turn (HS-2 aborts the turn rather than letting overhead balloon). The numeric budgets that back these (latency SLOs, per-pillar token caps) live in the SPEED + TOKENS charters in the sutra repo — linked, never restated here (D54).

Security in Native is enforced by hardstops at the access point, not by a separate perimeter: HS-3 denies cross-tenant access unless an explicit delegates_to edge exists, and HS-4 halts the whole turn rather than execute anything it cannot record. Both are operator-visible (a refusal message + recommended next action), and both have a named owning risk (R3, R2) in §4.10.3. The cloud channel's residency + key-isolation guarantees are deferred behind an activation gate; until then security is bounded by the operator-local machine (eng/compute).

ContractWhere it runs / livesStatus

Accuracy is a per-workflow KPI, not a single number: each task tier (T0-T3) and each pillar carries its own band, and the test runs before the system concludes (so CoS catches and silently retries its own failures rather than surfacing them). The v1 KPI table exists (§7.1.A). What is not settled — and is explicitly a founder gap — is the forward accuracy contract FQ2: which KPIs are canonical per tier, what test depth each phase needs, when test-before-conclude should degrade to test-by-sample for cost, and how accuracy compounds vs degrades over time. FQ2 is PROPOSED (2026-05-13), un-ratified, and chains the backlog rows T-G4-04..06.

6 · Reliability — no silent fail-open; retry then escalate

PromiseMechanism (home)Operator sees
No silent unaudited executionHS-4 halts on audit-unwritable (§4.10.1) · risk R2 (§4.10.3)"cannot record this decision; halting until audit recovers"
Retry budget then escalate (not infinite retry)§4.5 retry loop → ESCALATED failure state (§4.10.2)"auto-retry exhausted; your judgment needed" + 3-angle THINK
Partial side-effect reconciliationDEGRADED failure state (§4.10.2) · idempotent retry / manual log-write"step partially completed — message sent but audit row missed; reconciliation needed"
Connector-level transport reliabilityper-connector retry/flow contractscited at eng/connector (mechanism home, not copied here)

Reliability is the failure-state half of the §4.10 resilience contract: the §4.2 happy path (PROPOSED → ACTIVE → PERSISTED → RETIRED) is extended by three runtime failure states — PAUSED (hardstop or authority decision), ESCALATED (retry budget exhausted), DEGRADED (partial side-effect). The system never fails open silently: it either halts (HS-4) or surfaces the failure with a recommended next action and a reconciliation path.

Native's cost story has two halves: the runtime cost ceiling is governed (HS-2 caps governance overhead; the TOKENS charter caps tokens; R8 caps multi-agent spend per Charter), but the business cost model — what the operator pays — is an explicit placeholder. §6.2 names three tiers with price TBD pending operator-economics data, and R5 (pricing-model-wrong) is the owning risk. The v1→v2 move (per-Tenant subscription → outcome-based pricing) is a roadmap experiment, not a settled contract.

MECHANISM-PENDING (carried from master §4.10.1, not invented here): HS-4 · HS-5 · HS-6 · HS-7 · HS-8 are documented as canonical hardstops but the impl-vs-docs audit (§10.10 row 1) confirmed live detectors/executors do NOT yet exist in the shipped Native runtime — those rows are doctrine, mechanism pending. Resilience is the spine the other six attributes fall back to: when performance, security, accuracy, reliability, or cost breaches its target, the system enters a hardstop or a failure state rather than degrading silently. The §4.10 contract is the single home for that behavior — this cross-cut cites it; the per-part engineering pages (runtime, system-of-record, connector, authority-tenancy) own the per-mechanism detail.

Open gaps — founder queue

  • NF-FQ2 (founder gap, flagged per task) — Accuracy KPIs are not ratified. §C.6 FQ2 (T-G4-04 KPIs per tier, T-G4-05 test depth per phase, T-G4-06 test-before-conclude vs test-by-sample cost tradeoff) is PROPOSED 2026-05-13, not ratified. Blocks the accuracy section of this view from moving past v1 targets to a settled contract.
  • NF-1 — No single per-pillar token-budget table exists in the frozen doc; the budgets live in the TOKENS charter (canon). A doc-side numeric performance-budget table (latency SLO per surface + token cap per pillar) is the skeleton's Planned-section 1 intent and is currently a pointer-only. Founder ruling needed on whether to project charter numbers into the doc or keep them canon-only (D54).
  • NF-2 — Throughput KPI (OHS/wk per operator: ≥3 in 14d → ≥20 mature) is in the old skeleton spec but has no matching measured KPI row + drift signal in master §7 the way accuracy does. Needs promotion into a real Observability metric or explicit deferral.
  • NF-3 — Cloud-channel security (per-tenant data-residency + key isolation) + cloud cost/pricing tier are both deferred behind the same activation gate (master §6.x cloud / eng/compute deferred band). Until the gate opens, both security and cost are bounded to operator-local; the shared-host HS-3 extension is unspecified.
  • NF-4 — Resilience MECHANISM-PENDING: HS-4..HS-8 detectors not shipped (above). Resolution path per §10.10 P0 #1: either ship the missing detectors OR downgrade the canon entries to "doctrine, mechanism pending." Engineering owns, founder ratifies the downgrade if chosen.
