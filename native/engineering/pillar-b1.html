Cross-part invariants (the whole-pillar contract)

#Invariant — must hold ACROSS the partsWhy it is non-localGrounding
IV-1One-turn round-trip. A freeform utterance entering at UI returns parsed intent_type + structured sub-intents + a schema preview to the same surface within one turn, before any execution.The capture (UI), the parse (Host), and the echo (UI) are three parts; the “one turn” budget binds them as a unit — no single part page owns the budget.§2.B B1 acceptance; matrix UI cell
IV-2Typed-handoff contract. The Host emits intent_type + sub-intents against a pre-declared schema; Orchestration consumes exactly that typed object (not prose) to classify + find the process. Prose-only handoff is rejected.It is the contract between Host parse and Orchestration route — the seam the matrix only labels “intent parse” and the per-part pages each see from one side.ADR-012 (pnc-typed-parser-over-prose, D54); orch contracts table
IV-3State round-trip through SoR. Intake artifacts are written to B5.a (active session); the same turn may read B5 for shorthand interpretation. The write and the read are one round-trip, not two independent part actions.The non-local property is consistency: the intake the SoP writes must be the intake the next read sees — spans SoP + SoR within the turn.matrix SoR cell; §2.B B1 connectedness
IV-4Schema-before-call, validate-after-call. The output schema is shown before the LLM call (Host) and the post-LLM output is validated and rejected if non-conforming (SoP). The guard opens on one part and closes on another.A part-local view sees either the pre-declaration or the validation, never the bracket as one guarantee — the bracket is the pillar-level property.§2.B B1 acceptance; ADR-012 (D54)
IV-5Every statement captured (D17). A multi-statement turn is decomposed completely — parallel statements become parallel sub-intents; no statement is silently dropped between parse (Host) and fan-out (Orchestration).Completeness is checked across the parse→decompose hop; the dropped-statement failure mode lives in the seam, not in either part.D17 (§10.7 founder doctrine); ROUTE-I5 no-silent-skip (orch, D54)

#PropertySpansStatement (grounded; gaps flagged)

NP-2State round-tripSoP · SoRIntake-write to B5.a and shorthand-read from B5 form one consistent round-trip within the turn (IV-3); the matrix labels both edges but states no consistency/ordering rule — partial.
NP-3Security zoningA+T · UI · Host · DaemonIntake crosses the Authority + Tenancy boundary once at entry; the trusted-names shortcut (N09) skips the gate. Tenant isolation rides the Domain field on every primitive (ADR-006, D54). Per-block gate behavior inside the Daemon is not detailed — partial.

Open gaps — founder queue

  • NP-1 latency: no numeric per-step budget (ms) for the capture→parse→echo round-trip is stated in master §2.B B1 / §2.F.B — “within one turn” is the only bound. Needs a founder/FQ number.
  • NP-4 multi-intent fan-out: the mechanism that splits, orders, and re-joins parallel sub-intents (the Host parse → Orchestration fan-out seam) is not named in cited canon — mirrors the per-part orchestration “process finder mechanism not named” gap (orch gap 2).
  • NP-5 idempotency: ROUTE-I1 guarantees one routing_decision per input, but no dedupe rule for a re-sent identical utterance is stated. Open.
  • B1 Ring 1 (Problem space / Need / Solution direction) is awaiting-founder-fill on the product home (T-G1-02..04, §2.B B1); the operator-voice framing of this pillar is a founder cell, not engineering's to invent.
  • Ring 3 mechanism doc intent-layer-design.md (T-G3-01) is pending-design on the product home; this page is the cross-part LLD, the part-local Intent Layer mechanism rows live on engineering/orchestration.html.
  • PLATFORM-LOCK gate: Host, Orchestration, System of Process parents are NOT founder-LOCKED (BUILD-PROTOCOL cascade, codex MODIFY-7). The cross-part contract claims above inherit that gate — DRAFT until the spanned parents LOCK.
