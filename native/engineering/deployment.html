Cross-cut 6 — pull-not-push updates (§6.7; policy home on distribution)

The deploy property that ties the tiers together: updates are PULL by default. An operator chooses when their company's setup changes (doctrine D22, resolved at N33 on 2026-06-12). PUSH (forced auto-roll) is the override, reserved for security and foundational fixes, and always announces itself (release-note callout + audit row). This matches how the Sutra plugin behaves today — /core:update is a manual pull. The policy's primary home is distribution.html §6.7; this view cites it as the cross-cutting deploy invariant.

Update kindDefault mechanismOperator experienceCited home
Behavior-affecting Module updatePULL (operator initiates)"update available" signal; lands when operator pullsdistribution.html §6.7.1
Security / foundational fixPUSH (override, operator-visible)Forced roll + release-note callout + audit rowdistribution.html §6.7
SPEC update (plugin-rolled)Rides plugin channel (§6.4); operator-invisibleNo action; new SPEC active on next sessionmaster §6.4

Open gaps — founder queue

  • HS-4/HS-5 deploy-time detectors — doctrine, mechanism pending. Audit-unwritable (HS-4) and cutover-rollback-fails (HS-5) gate safe deployment but live detectors are not yet in the shipped runtime (master §4.10.1 MECHANISM-PENDING hedge). A deploy that cannot write DecisionProvenance should HALT per canon; verify the detector exists before relying on it. Owning detail: runtime.html + master §4.10.1.
  • Pricing per tier is a founder gap. §6.2 pricing is a placeholder flagged on distribution.html; deployment policy per tier is settled (cross-cut 5) but the commercial terms are not. Not this page's home — flagged for thread-completeness.
  • Cloud-hosted + partner-deployed channels are v2+. Today's deploy target is the per-operator local daemon. Cloud-hosted and partner-deployed channels are roadmap (master §6 channels; old skeleton "Distribution channels" section). No mechanism exists yet — do not document as shipped.
  • Daemon re-exec across plugin updates is asserted, not yet test-cited. "Re-exec across plugin updates without state loss" (cross-cut 2) is a master-spec claim; the test that proves state survives an update is not cited on the part page. Deploy-critical — route the verification ask to the runtime part page owner.
