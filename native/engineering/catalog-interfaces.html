C-2 — EngineEvents: the 26-event enum (event · payload · emitter · consumer · sink)

EngineEvents is the daemon’s internal event bus: 26 typed events, one canon part-file each under sutra/os/native/events/. The HLD Interfaces view (family I-2) lists them by family; this catalog adds the wire columns the skeleton planned — the payload field that uniquely shapes each event, the emitting part, the consuming part, and the JSONL sink. The full per-event schema · ordering invariant lives in canon (events/<event-name>.md, D54) and the emission invariants (exactly-one terminal, monotonic ts_ms, append-only) live one-home on eng/runtime (EngineEvent + RUN rows); the persistence + replay (fsync JSONL, 3-channel + stderr beacon) lives one-home on eng/observability. Enum + payload-field source: master §4.1 primitives EngineEvents catalog + §4.11; emitter/consumer/sink facts cited from eng/runtime (engine-event.md anchors) + eng/observability (ADR-013 sink).

Sink + replay (cited, owned one-home on eng/observability + eng/runtime): every EngineEvent is an append-only typed audit row — one JSONL line carrying event_type, ts_ms, execution_id?, payload, agent_identity (ADR-015). Sinks: ~/.sutra-native/user-kit/executions/E-<hash>.events.jsonl (per-Execution), user-kit/events.jsonl (global replay source), user-kit/decision-provenance.jsonl (DecisionProvenance subset), fsync-on-write per ADR-013. Invariants: monotonic ts_ms (events must not be reordered after persistence); append-only immutability (replay derives full state from the log); the 26-value event_type set is exhaustive — a new event type requires a NATIVE-ENGINE.md amendment + ADR and is mint-time-rejected. There is deliberately no audit_log_write_failed event type — HS-4 uses a stderr beacon, not an EngineEvent (canon gap, carried on eng/observability).

C-3 — Peer-Native A2A: the v1 log-only stub wire shape

The seventh inventory row, Peer-Native A2A, has no live wire in v1 — it is a log-only stub: the daemon records the intent to coordinate with a peer Native but does not transmit over any peer transport. Full agent-to-agent transport is gated to v2+. The HLD Interfaces view (family I-4) carries the v1-state / v2-gate split; this catalog states the v1 wire shape precisely so no reader infers a transport that does not exist. How the three registers compose — the whole-system reading

The per-part pages each answer “how does THIS part’s interface work.” Assembled as a wire-level catalog they answer the question no single page answers: what is the exact wire vocabulary the whole system speaks, and which part emits or owns each token of it? Read across the three registers, one invariant holds: every inbound token (a verified Connector message, an operator utterance) and every outbound token (a Connector send, a v2+ peer A2A frame) is named in C-1; every internal state transition that processing token produces is one of the 26 C-2 events; and every one of those events lands in the same append-only AUDIT sink, while every outbound send first passes the same Authority gate. C-3 is the one boundary still drawn as a stub — the peer A2A wire is logged-not-transmitted in v1. The mechanism-level proof of each clause lives one-home on the page named in its row; this catalog is the wire-level index that makes the interface vocabulary legible as a single surface.

Open gaps — founder queue

  • No live event-subscription / pub-sub API (v1): consumers read the durable JSONL replay source; there is no live event-stream subscription interface. Whether external observers (dashboards, non-terminal clients) need a streaming subscription API is a v2+/roadmap question — surfaced here, owned by roadmap. (gap-conservation)
  • No audit_log_write_failed event type: HS-4 signals an unhealthy audit sink via a stderr beacon, not via an EngineEvent — so the one failure that most needs to be audited is the one the event bus cannot record. Canon gap carried from eng/observability; reconciliation (beacon vs. event) is a canon-design question.
  • A2A envelope + logger absent (v1): the Peer-Native A2A row is log-only; the canon B16 envelope/logger and cross-Native identity/auth are DEFERRED with no authored protocol ADR (T-G2-09..12 / T-G3-06 pending-design). This catalog can only state the stub until that design lands. Owned by roadmap + eng/external-world.
  • Browser + Phone connector wire shapes undefined: auth source, identity/consent model, and payload envelope for Browser (T-G2-28..31, Charter TODO-005) and Phone (T-G2-24..27, v2+) are DEFERRED — their C-1 rows carry “DEFERRED” in the wire columns rather than an invented envelope. Owned by roadmap.
  • Cross-connector result ranking (F2) silent: canon is silent on how research results from multiple Connectors (Slack history + Email + web) are ranked when one ask hits several. An interface-semantics gap carried upstream from eng/connector (B6/F1 canon); affects the C-1 retrieval rows but has no wire answer yet.
  • Per-event payload schemas are canon-only: C-2 names the distinguishing field per event; the full typed schema + ordering invariant for each of the 26 events lives only in canon events/*.md (D54, not rendered here). This is by design (one-home / D54), recorded so the reader knows the rendered catalog is an index, not the schema source.
