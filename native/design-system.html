Tokens — color (core + semantic)

tokenvaluerole
--bg#FAFAF7page background, every surface
--panel#FFFFFFcards, panels
--ink#1A1714primary text
--stone#6B6560secondary text
--faint#B8B2A6tertiary/quiet text
--line#E8E3DBhairlines, borders
--cream#F5F0E8soft fills, deep-work blocks
--gold#B8945Fbrand accent: active nav, charter marks, NOW highlights
--clay#8B6B4Asemantic: DECIDE / held / approve actions
--steel#4A6B8Bsemantic: REVIEW / inbox / links
--forest#2D5A3Esemantic: DONE / proof / live status
--rose#8B4A6Bsemantic: NOW line / alerts / failing states

Rule: semantic colors ONLY carry involvement/status meaning (clay=decide, steel=review, forest=done, rose=alert). Never decorative.

Fifth semantic family (documented per B18-3): ok / warn / block — gate-verdict states used by governance surfaces (hook cards, gate banners). It is a separate family from the involvement four above: decide/review/done/alert describe the operator’s relationship to work; ok/warn/block describe a gate’s verdict on an action. The two never substitute for each other.

Surface rules (codex-locked)

surfacerule
APPdense, operational, restrained. Cards only for decisions/records. Greeting is the single serif moment per screen. No atmosphere.
EDITORIAL (homepage)larger rhythm, serif moments, gold particles allowed as atmosphere only — never on controls. Same tokens.
DIRECTORY (departments site)light information system. Inherits tokens + shared components; sheds its old visual logic. Content and URLs untouched.
DIVERGENCEexpensive by design: any variant needs (1) a named surface, (2) explicit token mapping, (3) a written rationale on this page. Otherwise it is a bug.
