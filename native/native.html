§3Build vs Invoke decision workflow

Every new capability requirement runs this gate before any code is written. Bias is toward invoke, not build.

For any new capability requirement:

   1. Check the 9-capability map. Already there?
        YES → invoke existing tool/standard.
        NO  → continue.

   2. Check Sutra-glue (Charter→Rego compiler, Default Composition,
      etc.). Covers it?
        YES → invoke existing Sutra-glue.
        NO  → continue.

   3. Load-bearing for current Workflow?
        NO  → defer (don’t build speculatively).
        YES → continue.

   4. Met by EXTENDING via 5 extension seams (metadata /
      schema_version / required_capabilities[] / extension_ref /
      discipline-tag)?
        YES → use the seam (no new build).
        NO  → continue.

   5. Build new component. Codex review. Apply Sutra-glue patterns.
Bias toward INVOKE, not BUILD.

§5One-turn wire flow

End-to-end, what happens when the founder asks Sutra to do something. Each tool has one job. Workflow code stays deterministic (no I/O).

USER: “Track Paisa loan application X status.”
   |
   v
[1] Default Composition matches → Workflow                  (Sutra glue)
    “track-loan-app”
   |
   v
[2] Temporal starts Workflow execution; assigns to worker      (Temporal)
   |
   v
[3] Activity loads Charter “loan-tracking”                    (OPA — in
    → Rego policy compiled                                     Activity)
    → OPA evaluates allow/deny
   |
   v
[4] Activity calls Anthropic Messages API                      (Anthropic
    body: prompt + mcp_servers=[paisa-tool, sheet-tool]         SDK + MCP)
    Claude reasons + calls MCP servers; returns output
   |
   v
[5] Activity emits DecisionProvenance via OTel SDK             (OpenTelemetry)
    OTel Collector queues + persists
   |
   v
[6] Workflow continues OR terminates per V2.4 §A12 T1–T6        (Temporal)
   |
   v
[7] Result + provenance trail returned to user                 (Sutra → user)

Determinism stays in the Workflow. All I/O (OPA evaluation, LLM calls, MCP tool invocation, provenance emission) lives in Activities. This is the codex r8 P1.1 fix folded in.
