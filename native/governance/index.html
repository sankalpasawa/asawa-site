D.6 Authority Model (cross-cutting)

Six dimensions gate Native's auto-execute vs ask-operator decisions. Applies cross-pillar — most heavily in B3 (action gate) and B4 (delegation through Native to humans). Block internals: platform/authority-tenancy.html (primary home; this is the operator-facing summary).

DimensionWhat it gates
by domainNative acts in one company's domain but not another (per Charter)
by toolNative can call Slack but not bank-API without auth
by stakeholderNative emails team but escalates board/regulator
by dollar threshold≤$X auto; >$X ask
by reversibilityreversible auto; irreversible ask
by confidence levelhigh-confidence auto; low-confidence ask

D.7 CX Bar (cross-cutting)

Quality bar Native's experience must clear — applies to every pillar.

  • Feels like a good Chief of Staff, not a robot
  • Scannable output; operator decides in <30s of reading
  • Low friction; routine work doesn't interrupt
  • Brainstorm partnership feels collaborative, not deferential
  • Errors surface clearly with retry, never silently

D.8 Operator-First Lens (cross-cutting)

Native's loyalty is to the operator personally; org is the mission frame, not the master. Shapes context ranking, escalation, memory formation in every pillar.

  • B2 ranks context by what serves the operator's decision
  • B3 escalation defaults favor operator's pace, not org SLAs
  • B5 memory is per-operator + per-Charter; org-Tenant artifacts visible by ACL
  • Conflict between operator preference and org policy: surface to operator, never auto-resolve to org

D.9 Scope anti-pattern (cross-cutting)

Native v1 is NOT — explicit scope guardrails.

  • NOT a day manager (no calendar / todos)
  • NOT a chatbot (workflow-shaped, not conversational)
  • NOT a memory product (governance + multi-tenant + emergence are the value)
  • NOT a full-autonomy agent (operator-in-loop is core)
  • NOT a calendar / inbox / task-list (substantive cognitive work only)

D.10 Charter Model (Native platform primitive · cross-cutting)

Charter is a Native platform primitive — an operator-set behavioral contract that scopes a deployed workforce instance (e.g., the CoS product) over time. Each Charter is either fixed (rules locked) or flexible (rules adapt with operator approval).

Charter modeWhat it meansExample
FixedScope + decisions + authority + tools all locked at Charter creation; Native cannot expand without operator re-charter"Run weekly P&L close — only these tools, only this audience, escalate on deltas >$X"
FlexibleScope + tools may extend within declared bounds; Native proposes, operator ratifies; learned patterns become standing rules"Run BillU GTM brainstorm — adapt method based on what works, propose new tools as needed, escalate before external comms"

Charter mode interacts with D.6 Authority Model: fixed Charters set conservative authority defaults; flexible Charters allow authority to widen with operator approvals. Anchored to T3 Charter tier in A.7.

D.11 Method Selection (Native platform primitive · cross-cutting)

Method Selection is a Native platform primitive. Different work classes need different intelligence — Native routes per task tier (A.7) to the right model, tool set, and decision pattern. CoS (the deployed product) consumes this routing without re-implementing it.

Task tierOptimization targetMethod profile
T0 AtomicSpeed; minimize tokensFast model · single LLM call · narrow tool set · no escalation
T1 Multi-actionReliability across N stepsStandard model · per-step verify · tool-routing · gate on external comms
T2 IterativeResponsiveness; low-latency refinementFast model · short context window · 1-min iteration loop · zero gate on minor edits
T3 CharterLong-horizon quality + judgmentBest-available model · max context · multi-method ensemble · gates at goal-transition points

Method selection is Ring 2 contract material (what Native commits to per task tier). Method routing engine internals live in Phase 2 design — see action-engine-design.md.

D.12 Artifact Governance (cross-cutting)

Combined Artifact Discipline (form) + Artifact Integrity (lifecycle). Every artifact Native produces must satisfy both surfaces. Per codex+deepseek R5 convergence: separating these two invites duplicate rules + drift.

D.12.1 Form discipline — transform text prose → technical-specific documents

RuleWhat it means
Right artifact shape per taskPlans → checklist · designs → ASCII diagram + table · decisions → ADR · code outputs → versioned source files · data → typed schema. Default text only when nothing else fits.
Visual + structured + wholeFor ≥3 items: table > prose · for decisions: ASCII-boxed callout · for scores: progress bar · for flows: ASCII diagram. Double presentation (visual + text) acceptable.
LLM-future-readableASCII diagrams over images (machine-readable). Mermaid-style text diagrams acceptable. Avoid screenshots unless source-of-truth.
Scientific appropriatenessUse the format that the discipline uses (Gantt for time-plans, swim-lane for processes, dependency-graph for systems, ER for data, sequence for protocols).

D.12.2 Lifecycle integrity — append-not-overwrite

RuleWhat it means
Append, don't overwriteEvery change adds a version (semver or date-stamped); the prior version stays accessible. No silent rewrites.
Notify-on-changeWhen an artifact shared with audience X changes, audience X is notified by §5 Connector (Slack / email per Charter).
Reference-with-versionEvery cross-reference embeds the version it points to (e.g., paisa-Q3-onepager@v3 not paisa-Q3-onepager). Resolves to that exact version even after newer versions ship.
Pristine boundariesArtifact identity stays stable. Metadata (owner, version, source-of-truth status) travels with the artifact, not in a sidecar that can desync.
Audit-traceableEvery artifact write produces a DecisionProvenance row (§4 Native audit substrate) linking creator-Charter + reason + diff-from-prior.

D.12.3 Acceptance criteria (Artifact Governance v1)

  • 100% of Native-produced artifacts carry version + owner + Charter-ref metadata.
  • Zero silent overwrites (HS-4 fires on any write that replaces without version-bump).
  • Notify-on-change reaches audience within 60s of change for Slack/email channels.
  • Cross-references resolve to versioned target; broken references surface to operator (don't silently 404).

D.13.3 Why directions ARE a Native product feature
