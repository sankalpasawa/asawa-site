Authority Model — 6 gate dimensions (D.6) Six dimensions decide auto-execute vs ask-operator: by domain (per-Charter company scope), by tool (Slack yes, bank-API no without auth), by stakeholder (team auto, board/regulator escalate), by dollar threshold (≤$X auto, >$X ask), by reversibility (reversible auto, irreversible ask), by confidence level (high auto, low ask). Applies cross-pillar, heaviest in B3 action gate + B4 delegation. d6-authority
Ask-vs-act decision cascade (F.1 + F.5) Ordered 4-question cascade per action: irreversible? → ASK multi-step confirm ("type go"); high-risk (spend/send/share/commit touching people or money)? → ASK one-tap confirm; new authority (no prior permission template)? → ASK grant once / grant always / not now; first time on channel/contact? → ASK preview-before-send. All no → ACT, report after. section-2-f-6-trust-authority
Reversibility tags (F.2) Every action carries a visible reversibility tag: Reversible (undo window, "say undo anytime"), Reversible with effort (retract/re-issue/re-pay — doable, not free), Not reversible (confirming locks it in). section-2-f-6-trust-authority
Trust ladder (F.4) Autonomy earned over time, 4 rungs: Rung 1 (day 0-14) ask before every external action; Rung 2 (15-45) auto-act on repeated patterns, ask on novel; Rung 3 (46-90) auto-act on routines, ask only high-risk/irreversible; Rung 4 (90+) runs standing routines, surfaces what it did. Operator can dial up/down explicitly at any rung. section-2-f-6-trust-authority

How it flows internally

Every access entering the wrap is classified by the D.6 six-dimension Authority Model (domain · tool · stakeholder · dollar · reversibility · confidence), then run through the F.5 ask-vs-act cascade (irreversible → high-risk → new-authority → first-time-channel → else ACT-and-report); any ASK outcome is realized by the approval-gate primitive (ADR-009), which surfaces the prompt up through UI carrying its F.2 reversibility tag, while the gated workflow inside System of Process holds in PAUSED or ESCALATED until the operator's decision flows back down. In parallel, the tenancy half checks every System-of-Record touch against the ADR-006 Domain field, with HS-3 default-denying cross-tenant access lacking an explicit delegates_to edge; denials surface via the hardstop UX contract (WHAT + next action + audit-row link). Operator responses ("grant always", dial up/down) feed the F.4 trust ladder, which shifts future cascade outcomes from ask toward auto over rungs 1-4; every decision through the gate writes a DecisionProvenance row, which the F.3 replay surface reads back on demand, and the §1.5.1 guard tooling enforces the same contract at action-time as HARD/SOFT blocks.
