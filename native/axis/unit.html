What a unit looks like AXIS · pictures DRAFT v1

One primitive: value and axis. A unit is one value on every axis, at one version. Every picture below is drawn from that, in the site's own words.

Read with Completeness of thought (the questions) and Axes and families (the frame, the sorting test, every named axis). The nine lines of the theory this page draws were ruled on 2026-10-26; the sources are named under every picture.

0 · The axis: where it comes from

A value seen once is a point in the record. Seen again and again, the points line up. Reflection lifts that line into an axis and names its answers. The sorting test then says which family the axis belongs to.

  1. 1Values in the record: the same answers keep recurring (here: who may let a transition pass).
  2. 2Reflection lifts them into one line, the axis, and names its answers: auto, ask, deny. The answers must be mutually exclusive and collectively exhaustive.
  3. 3The sorting test asks what the axis reads and places it in one family: this one gates a transition, so GOVERN.
  4. 4Every unit now carries one more row and holds one value on it. A minted axis then passes the retention gate or is retired.

1 · One unit

A unit is one value on every named axis, at one version. The six families are the bands, the named axes are the rows, the lit dot is the value this unit holds now.

  1. 1The unit: one list of values across all axes, at one time. The smallest unit is the work atom: one goal, one check.
  2. 2A band is a family: what the axis reads, by the sorting test. A minted axis is sorted into a band and adds one row to every unit.
  3. 3A row is a named axis: one question.
  4. 4A lit dot is the value held now. Where the site names the values they are written out; where it does not, the dot stands alone.
  5. 5Two lit dots on one row: several values at once, if they do not contradict. The rule for which may co-occur is open.
  6. 6The corner tag is time. Versions are kept by supersedes: the new one written, the old one kept, never overwritten.

2 · Kinds of units: the ladder

Same unit, different values, at every rung of the ladder: base case, root, department, engine, workflow, work atom. A meta unit is a unit that holds units.

codify: personcodify: improvised call or checklistcodify: codemeta unit
  1. 1The ladder: base case (a first stamp, recorded) > root (makes departments) > department (holds engines) > engine (steps, drawn by Adaptation) > workflow (work atoms in an order) > work atom (one goal, one check).
  2. 2Kinds are not different shapes. They are different values on the same axes, chiefly GROW's codify rung, which tints the header.
  3. 3The founder's word "meta unit" is any rung above the atom. It holds units and is itself a unit, with its own values: the strip on its frame.
  4. 4Principle 2, one rule that recurses: at every level the same four things, a goal, an owner, rules, a budget. The rule that makes a department the same way at every level is proposed, not built.
Sources

The ladder and the three principles: Axes and families, "The frame, in one notation" and "Three principles from nature". The rungs: S-03 crystallization spectrum on A department. The levels organisation to atom: The structure.

3 · Units interact: edges, asks, stamps

Units are atoms on a graph. An EDGE handoff carries an artifact. An ask goes up to the owner, a stamp comes down. The input a unit needs is read fresh over an edge.

artifact, on a handoffask up (Propose), stamp down (Decide, Delegate)the recordexternal system
  1. 1Who it interacts with is not an axis value. It is an EDGE between two atoms: handoff, shared resource, must-cohere.
  2. 2Only an artifact crosses an edge. A unit consumes artifacts and produces artifacts: "a company is artifacts and the work between them".
  3. 3Only an ask or a stamp crosses a level. The four stages: Decide, Delegate, Deliver, Propose. Top to bottom is Realization and Delegate; bottom to top is Reflection and Propose.
  4. 4The founder's "question to the meta unit" is an ask. The answer is a stamp: go, ask, refuse, always. An ask stamped the same way again and again becomes a go rule: the standing instruction.
  5. 5Knowledge is the input, read fresh every run (SHAPE), over an edge from an artifact or an external system.
  6. 6Deliver: the output leaves over an edge to the outside. The record keeps every version of every artifact.
Sources

Edges: EDGE, the three kinds. Artifacts: Artifacts and work. The stages and actors: The frame. The go rule: the GOVERN row of the moves table on Axes and families.

4 · Across time and space

One scene, six moments. Rows are places, left to right is time. A value changes and the unit supersedes itself; a goal changes and a new work atom is minted.

Why each moment goes the way it does
The ruleA situation arrives; the owner answers with one of two moves: change a value (same unit, next version by supersedes) or mint a new work atom (one goal, one check).
t2RESOURCE's token budget changed; the goal did not. Same unit, v2 supersedes v1.
t3A new goal. A goal is identity, so a new work atom is minted. The old one hands it an artifact on a handoff.
t4The new atom finds its goal contradicts a fact and raises an ask (Propose). The owner stamps "always": a go rule, lit on its GOVERN authority row.
t5The first atom delivers outside and retires; every version is kept. Unretire, a retire reversed from its manifest, is built in the record.
What would change itIf constraints are identity too, t2 splits. If the goal is not identity, t3 is a value change and no atom is born. Founder's call.

5 · Runs across, versions down

A version is the unit updated. A run is the unit executed at one version. Inside a run: steps, the artifacts they write, the output handed on. The record keeps every step and artifact of every run; Reflection reads it across runs and writes the next version.

step: an LLM call or a deterministic action, with a checkartifact written by a stepthe record, read across runs
  1. 1Across: runs. Anyone can start a run: a person, an AI, a rule, another piece of work. Each run reads the input fresh (SHAPE). The input differs, the unit does not.
  2. 2Inside a run: steps in an order, each with a check; some steps write artifacts; the last artifact handed on an edge is the output.
  3. 3A run whose check fails writes no output. The record still keeps its steps.
  4. 4Down: versions. What accumulates on the unit across runs (GROW) is lifted into the next version. A record line lifted to its rule is Reflection.
  5. 5The pointer: how far the current run has gone. The founder's "where in Realization is this unit". No named axis yet work needs to be done.
  6. 6A run never edits the unit; a version never runs. The output crosses an edge; the record stays on the unit and feeds the next version.
The correlation the founder asked for, and sources

"Output, an accumulation of actions and artifacts" is two things on the site: the output (the artifact delivered, Deliver) and the record (every step and artifact, kept). Realization is the run: the goal cut into steps down to one goal, one check. Reflection is the version: the record lifted into a rule. Sources: the sorting test (SHAPE reads the input fresh every run; GROW accumulates on the unit across runs) and the moves table on Axes and families; "anyone can start a run" on the TIME spec; steps as an LLM call or a deterministic action with a pre-declared output and a post-call check on Engines, workflows, skills; versions by supersedes on Artifacts and versions.

6 · How a value is set by the situation

Four ways, and every named axis uses at least one: cut from the parent, read from the input, stamped by the owner, lifted from the record.

  1. 1Cut (Realization, down): the parent's value is split into the children's. A goal into child goals; a budget among the children; a deadline into step durations; a parent's rules into a child's tighter rules.
  2. 2Read (SHAPE, fresh each run): classified from the input every turn. Type, certainty, lens are written every turn before any work.
  3. 3Stamped (GOVERN): the owner sets it by hand. Go, ask, refuse, always; a cadence of manual, daily or weekly; a proposed child or engine stamped in.
  4. 4Lifted (Reflection, up): the record across runs becomes the next value. What was spent becomes the next budget line; the beats observed become the cadence; an ask stamped the same way again and again becomes a go rule.

7 · How a new axis is minted

Users mint axes freely; the family skeleton stays closed. A minted axis passes the pick test, then the five steps. Only escalate can change the families, and only the core author does that.

  1. 1Mint: a user keeps hitting an unnamed dimension and names it as a value, via value and axis.
  2. 2The pick test: does it change what is built, or who reads? Five outcomes: keep, merge (overlaps an existing axis), rename (same axis, clearer label), reject (changes neither; dropped, logged, not silent), escalate (passes but fits no family).
  3. 3Keep runs the five steps. P1 name and define: the sorting test gives it one family. P2 show: need, advantage, how, one example. P3 thread: onto the page its family points to. P4 cross-link: which record it reads, which joint it writes back to. P5 ratify: a numbered D-direction or ADR.
  4. 4Escalate goes to the core author, who may rework the families: a new family, a split, a merge. Rare, governed, never on the fly.
One walked: "compliance", and the sources

A user runs a regulated workflow and keeps hitting: does this action satisfy a binding external rule? They mint "compliance". P1 sorts it to GOVERN (it gates whether an action is allowed); P2 gives its ladder ok, review, blocked; P3 threads it onto the authority page as a new gate dimension; P4 cross-links it to the record it reads and the write-backs it gates; P5 ratifies it as an ADR. No re-architecting. Source: Making an axis (the five steps, a new axis walked, the retention gate) and the open-axis rule. Pending on the site: ratifying the open-axis rule as a numbered D-direction.
