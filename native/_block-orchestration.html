Multi-turn context carry Per §2.F.B.3, five things persist across turns/sessions to resolve references: recent intent (last 3-5 asks), named entities, active charter (standing directives), deferred follow-ups (re-enter context at the right moment), and open questions Native asked but the operator hasn't answered. section-2-f-2-input-intent
Confidence gate (confirm-back) Per §2.F.B.4, four confidence bands: High → proceed (confidence shown only on request); Medium (object ambiguous) → yes/no confirm then proceed; Low (intent unclear) → "I read this as a task — is that right?"; Very low → "act, answer, or remember?". Operator is never surprised by what Native thought they meant. section-2-f-2-input-intent

How a request moves through the block

An operator request enters from the Host (freeform utterance arriving via the §2.F.B.1 modalities, or a scheduled/cadence/event Trigger fired by the daemon). The Intent Layer parses the utterance into typed intent + sub-intents against a pre-declared output schema (post-LLM validated, non-conforming output rejected); the intent classifier resolves it to one of five types (Task/Query/Directive/Feedback/New Idea) using its 'tell', drawing on the multi-turn context carry (recent intents, named entities, active charter, deferred follow-ups, open questions) to resolve references like "do that again for the other client". The result hits the confidence gate: high confidence proceeds; medium/low/very-low loops a confirm-back question out through the Host to the operator before proceeding. The fan-out router then maps the typed intent to its journey, and the process finder selects the relevant process — handed down to System of Process on the "task = process" edge. Authority + Tenancy gates every access along the way.
