§2.A Idea — CoS product #

The WHY for CoS specifically. Problem · persona · anti-persona · vision · differentiation · scope · task taxonomy · actors. Operator-first; org is the mission frame, not the principal.

A.1 Problem statement #

Awaiting founder fill. Working frame: operator juggles N streams of work with sub-linear team scaling; existing assistants are conversational or chore-based; nothing compounds across the founder's actual work.

A.2.2 Zero-terminal product constraint (post-onboarding · v1 + onward)

Hard rule (post-onboarding): after the one-time onboarding done by Asawa/Sutra Forge (per §6 Distribution), the operator never sees terminal commands, installation steps, or system internals during ongoing operation. Native is invisible during use. CoS surfaces only the operator's work (the 5 pillars). Any technical step (install · update · connect · authorize) is one-time setup done by Asawa/Sutra Forge or auto-onboarded via the Sutra plugin — not the operator. Operators don't type terminal commands. Operators don't read Sutra internals. CoS speaks the operator's domain language, not Native vocabulary. Scope clarification: v1 wedge requires terminal-fluent operator (per §A.6 + ratified Q2/Q9) — meaning operator CAN handle the one-time onboarding via terminal if needed; post-onboarding the operator works in their domain language only, never the terminal.

A.4 Vision #

Native is a workforce-deployment platform — it scopes, deploys, and supervises a workforce of agents under Charters, with Method routing, Authority gates, and a full audit trail.

Chief of Staff is the first product deployed on Native. CoS frames the operator's work, executes end-to-end where the path is known, surfaces decisions where operator judgment is needed, and closes the loop by writing what was decided + what shipped back into the substrate so the next iteration starts further ahead. CoS is an implementation consultant for the operator — accountable through the loop, not a day-organizer.

Every utterance + decision + outcome enters a compounding cognitive substrate. The operator's next ask is answered faster because the deployed CoS (running on Native) already knows the operator's patterns, charters, and history.

A.9 Customer Skill Modes — how CoS adapts surface to each operator #

Operators show up with different levels of clarity about what they want. CoS adapts its working mode per task (could be different across tasks for the same operator). Skill mode is detected from the operator's utterance, prior patterns (B5.d), and Charter scope.

Skill modeCustomer stateCoS working modeAuthority default
SM1 — Idea only"I want X but I don't know the output shape or how to get there"High-touch. CoS proposes output shape + asks for ratification + then auto-executes. B3a THINK heavy.Conservative — ask before any external effect.
SM2 — Idea + output"I want X, should look like Y, don't know how"Medium-touch. CoS pure auto-execute path + presents Y. B3b DO heavy.Default Authority Model (D.6) thresholds.
SM3 — Idea + output + how"I want X, looks like Y, here's how — execute"Low-touch. CoS pure execution + delivers. Operator's HOW manifest used directly.Aggressive — operator's HOW signals trust.

Example customer mapping

  • Testlify CEO — primarily SM2 (knows desired output formats; relies on CoS for how). Sometimes SM1 for new strategic asks.
  • Dharmik Chief of Staff — primarily SM3 (highly operational; defined workflows). Sometimes SM2 for novel asks.
  • Healthtech PM — mix of SM1 and SM2 depending on whether discovery or execution.
  • Neurics head-of-sales co-founder — primarily SM2 for sales workflows; SM1 for strategic decisions.

Cross-references — Skill mode detection feeds HOW Engine (§3) detailing dimension. Authority gate (D.6) defaults per skill mode. Operator satisfaction signals (§7) include "skill-mode misdetection rate" — when CoS reads SM2 but operator was actually SM1.

B3a — THINK #

Brainstorm partnership; identifies "this is a brainstorm decision" moments; partners with operator on ideation. Iterative refinement is first-class: operator says "adjust this not that" — Native treats it as refinement on existing context, not a fresh ASK.

B3b — DO #

Auto-execute end-to-end when path is known. Idea → plan → execute → standing pattern (operationalization). Method-routing: different problem classes get different solving strategies.

B3c — PRESENT #

Operator-facing output rendered for decision-speed. Scannable. Actionable. Native's findings surfaced in a format that supports the operator's "make decision and move" mode.

§2.E User Journey Modes — 5 states the operator experiences #

CoS experience changes shape across 5 operator states. Same product, different surface emphasis per state. The system supports all 5 concurrently for one operator (they overlap in time across companies).

§2.E.1 The 5 states

StateWhat's happeningDominant pillar emphasisCoS posture
S1 Single taskOperator asks one discrete thing; CoS completes one turn end-to-end.B1 → B2 → B3 → (B4 if comms) → B5Crisp · scannable output · low-touch

§2.E.2 State transitions

   S1 single task ──completes──▶ S2 multi-task (if 2+ tasks in flight)
   S2 multi-task ──promotes──▶  S3 project (when task graduates to Charter)
   S3 project ──concludes──▶    S2 multi-task OR S4 engagement (if recurring)
   S4 engagement ──scales──▶    S5 whole-system (when across portfolio)
   S5 ─────────────────────────▶ ALL OTHER STATES active concurrently

   Native platform (§4) tracks state per Charter + per task.
   CoS adapts surface per dominant state.

§2.E.3 What's needed per state (acceptance)

  • S1: ≤1-turn parse + execute + present (per T0/T1 acceptance criteria).
  • S2: zero lost-context on session restart · N24 "5 in-flight tasks straight" need satisfied.
  • S3: Charter milestone gates emit progress updates · operator can replay plan-evolution.
  • S4: B5.d learned patterns surface in B2 retrieval · operator's voice signal stays consistent across pillars (B4 audience-calibrated).
  • S5: Daily Pulse aggregates · cross-portfolio priority view available · workforce health (Charter status across all companies) visible.
